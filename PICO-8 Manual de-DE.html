▨ Willkommen bei PICO-8!

PICO-8 ist eine Fantasie-Konsole zum Erstellen, Teilen und Spielen von kleinen Spielen und anderen Computerprogrammen. Wenn du sie einschaltest, begrüßt dich die Maschine mit einer Shell zum Eingeben von Lua-Programmen und bietet einfache integrierte Werkzeuge zum Erstellen von Sprites, Karten und Sounds.

Die strengen Einschränkungen von PICO-8 wurden sorgfältig ausgewählt, um Spaß bei der Arbeit zu bieten, kleine, aber ausdrucksstarke Designs zu fördern und hoffentlich den PICO-8-Kassetten ihren ganz eigenen Look und Feel zu verleihen.

▨ Technische Daten

Display:    128x128, feste 16-Farben-Palette
Eingabe:    6-Tasten-Controller
Kassetten:  32 KB Daten, kodiert als PNG-Dateien
Sound:      4 Kanäle, 64 definierbare Chip-Sounds
Code:       P8 Lua (max. 8192 Code-Token)
CPU:        4 Mio. VM-Befehle/Sek.
Sprites:    Ein Bank mit 128 8x8-Sprites (+128 gemeinsam genutzt)
Karte:      128 x 32 Kachelkarte (+ 128 x 32 gemeinsam genutzt)

❶ Erste Schritte

1.1 Tasten

ALT+ENTER: Vollbild umschalten
ALT+F4:    Schnell beenden (Windows)
STRG-Q:    Schnell beenden (Mac, Linux)
STRG-R:    Cartridge neu laden / ausführen / neu starten
STRG-S:    Aktuelle Cartridge schnell speichern
STRG-M:    Ton stummschalten / Ton wieder einschalten
ENTER / P: Pausenmenü (während der Cartridge läuft)

Standardtasten für Spieler 1: Pfeiltasten + ZX / NM / CV
Standardtasten für Spieler 2: SDFE + Tab, Q / Umschalt + A

Um die Standardtasten zu ändern, verwende das KEYCONFIG-Dienstprogramm innerhalb von PICO-8:

> KEYCONFIG

1.2 Hello World

Nachdem PICO-8 gestartet ist, gib einige dieser Befehle ein und drücke anschließend die Eingabetaste:

> PRINT("HELLO WORLD")
> RECTFILL(80,80,120,100,12)
> CIRCFILL(70,90,20,14)
> FOR I=1,4 DO PRINT(I) END

(Hinweis: PICO-8 zeigt nur Großbuchstaben an – tippe einfach normal ohne Feststelltaste!)

Du kannst ein interaktives Programm erstellen, indem du Befehle wie diese im Code-Bearbeitungsmodus zusammen mit den beiden speziellen Callback-Funktionen _UPDATE und _DRAW verwendest. Mit dem folgenden Programm kannst du beispielsweise einen Kreis mit den Cursortasten bewegen. Drücke Esc, um zum Code-Editor zu wechseln, und gib den folgenden Code ein oder kopiere ihn und füge ihn ein:

X = 64 Y = 64
FUNCTION _UPDATE()
  IF (BTN(0)) THEN X=X-1 END
  IF (BTN(1)) THEN X=X+1 END
  IF (BTN(2)) THEN Y=Y-1 END
  IF (BTN(3)) THEN Y=Y+1 END
END
 
FUNCTION _DRAW()
  CLS(5)
  CIRCFILL(X,Y,7,14)
END

Drücke nun Esc, um zur Konsole zurückzukehren, und gib RUN ein (oder drücke STRG-R), um das Programm in Aktion zu sehen. Für komplexere Programme schau dir bitte die Demo-Kassetten an (gib INSTALL_DEMOS ein).

Wenn Sie Ihr Programm für später speichern möchten, verwenden Sie den Befehl SAVE:

> SAVE PINKCIRC

Und um es wieder zu laden:

> LOAD PINKCIRC

1.3 Beispiel-Kassetten

Diese Cartridges sind im Lieferumfang von PICO-8 enthalten und können durch Eingabe folgender Befehle installiert werden:

> INSTALL_DEMOS
> CD DEMOS
> LS

HELLO     Grüße von PICO-8

WANDER    Einfacher Walking-Simulator

Um eine Cartridge auszuführen, öffne PICO-8 und gib Folgendes ein:

> LOAD JELPI
> RUN

Drücke die Escape-Taste, um das Programm zu beenden, und noch einmal, um in den Bearbeitungsmodus zu gelangen.

Eine kleine Sammlung von BBS-Kassetten kann auch mit folgendem Befehl unter /GAMES installiert werden:

> INSTALL_GAMES

1.4 Dateisystem

Mit diesen Befehlen können Sie Dateien und Verzeichnisse (Ordner) verwalten:

LS          das aktuelle Verzeichnis auflisten
CD BLAH     Verzeichnis wechseln
CD ..       ein Verzeichnis höher gehen
CD /        zurück zum obersten Verzeichnis wechseln (auf dem virtuellen Laufwerk von PICO-8)
MKDIR BLAH  ein Verzeichnis erstellen
FOLDER      das aktuelle Verzeichnis im Dateibrowser des Host-Betriebssystems öffnen

LOAD BLAH eine Cartridge aus dem aktuellen Verzeichnis laden SAVE BLAH eine Cartridge im aktuellen Verzeichnis speichern

Wenn du Dateien verschieben, duplizieren oder löschen möchtest, verwende den Befehl FOLDER und führe die Aktion im Host-Betriebssystem aus.

Der Standardpfad für das Laufwerk von PICO-8 lautet:

Windows: C:/Users/Yourname/AppData/Roaming/pico-8/carts
OSX: /Users/Yourname/Library/Application Support/pico-8/carts
Linux: ~/.lexaloffle/pico-8/carts

Du kannst diese und andere Einstellungen in pico-8/config.txt ändern

Tipp: Das Laufwerksverzeichnis kann einem Cloud-Laufwerk (z. B. von Dropbox, Google Drive oder ähnlichen Anbietern) zugeordnet werden, um eine einzige Festplatte zu erstellen, die von PICO-8-Instanzen auf verschiedenen Host-Rechnern gemeinsam genutzt wird.

1.5 Laden und Speichern

Bei der Verwendung von LOAD und SAVE kann die Dateiendung .P8 weggelassen werden und wird automatisch hinzugefügt.

> SAVE FOO
SAVED FOO.P8

Cartridge-Dateien können auch per Drag & Drop in das PICO-8-Fenster gezogen werden, um sie zu laden.

Die Dateiendung .p8.png schreibt die Cartridge in ein spezielles Bildformat, das wie eine Cartridge aussieht. Die Endung .p8.rom schreibt in ein rohes 32k-Binärformat.

Verwende den Dateinamen „@clip“, um in die Zwischenablage zu laden oder dort zu speichern.

Verwende den Dateinamen „@url“, um den Inhalt als URL für pico-8-edu.com in die Zwischenablage zu speichern, sofern er in 2040 Zeichen kodiert werden kann (nur Code und Grafiken).

Sobald eine Cartridge geladen oder gespeichert wurde, kann sie auch mit STRG-S schnell gespeichert werden

■ Speichern von .p8.png-Kassetten mit Textbeschriftung und Vorschaubild

Um ein Beschriftungsbild zu erstellen, das mit der Cartridge gespeichert wird, führen Sie das Programm zuerst aus und drücken Sie STRG-7, um den aktuellen Bildschirminhalt zu erfassen. Die ersten beiden Zeilen des Programms, die mit „--“ beginnen, werden ebenfalls auf die Beschriftung der Cartridge gezeichnet.

-- OCEAN DIVER LEGENDS
-- BY LOOPY

■ Beschränkungen der Code-Größe für die Formate .p8.png / .p8.rom

Beim Speichern im .png- oder .rom-Format muss die komprimierte Größe des Codes weniger als 15360 Bytes betragen, damit die Gesamtdatenmenge <= 32k ist.

Um die aktuelle Größe deines Codes zu ermitteln, verwende den Befehl INFO. Die Beschränkung der komprimierten Größe gilt nicht für das Speichern im .p8-Format.

1.6 Verwendung eines externen Texteditors

Es ist möglich, .p8-Dateien direkt mit einem separaten Texteditor zu bearbeiten. Wenn Sie STRG-R drücken, um eine Cartridge auszuführen, wird die Datei automatisch neu geladen,

wenn:

1. keine ungespeicherten Änderungen in den PICO-8-Editoren vorliegen UND
2. sich der Inhalt der Datei von der zuletzt geladenen Version unterscheidet.

Wenn sowohl an der Cartridge auf der Festplatte als auch im Editor Änderungen vorgenommen wurden, wird folgende Meldung angezeigt:

DIDN'T RELOAD; UNSAVED CHANGES

Alternativ können .lua-Textdateien in einem separaten Editor bearbeitet und dann bei jeder Ausführung der Cartridge mithilfe von #INCLUDE (an der gewünschten Stelle im Code) in den Code der Cartridge eingebunden werden:

#INCLUDE YOURFILE.LUA

1.7 Backups

Wenn Sie das Programm beenden, ohne Änderungen zu speichern, oder eine vorhandene Datei überschreiben, wird eine Sicherungskopie der Cartridge unter {appdata}/pico-8/backup gespeichert. Eine zusätzliche Kopie der aktuellen Cartridge kann ebenfalls in demselben Ordner gespeichert werden, indem Sie BACKUP eingeben.

Um den Ordner „backups“ im Dateibrowser des Host-Betriebssystems zu öffnen, verwenden Sie:

> FOLDER BACKUPS

Anschließend können Dateien per Drag & Drop in das PICO-8-Fenster gezogen werden, um sie zu laden.

Ab Version 0.2.4c werden außerdem alle 20 Minuten regelmäßige Sicherungen erstellt, wenn der Editor nicht im Leerlauf ist, was bedeutet, dass der Sicherungsordner alle 5 Stunden um etwa 1 MB wächst. Dies kann in der Datei config.txt deaktiviert oder angepasst werden

1.8 Konfiguration

PICO-8 liest zu Beginn jeder Sitzung die Konfigurationseinstellungen aus der Datei „config.txt“ und speichert sie beim Beenden (Sie sollten die Datei „config.txt“ also bearbeiten, wenn PICO-8 nicht läuft).

Der Speicherort der Datei „config.txt“ hängt vom jeweiligen Betriebssystem ab:

Windows: C:/Users/Yourname/AppData/Roaming/pico-8/config.txt
OSX: /Users/Yourname/Library/Application Support/pico-8/config.txt
Linux: ~/.lexaloffle/pico-8/config.txt

Verwende den Schalter -home (siehe unten), um einen anderen Pfad zum Speichern von config.txt und anderen Daten zu verwenden.

Einige Einstellungen können während der Ausführung von PICO-8 durch Eingabe von CONFIG SETTING VALUE geändert werden. (Geben Sie CONFIG allein ein, um eine Liste anzuzeigen.)

▨ Controller-Einrichtung

PICO-8 verwendet das SDL2-Controller-Konfigurationsschema. Es erkennt gängige Controller beim Start und sucht außerdem nach benutzerdefinierten Zuordnungen in der Datei sdl_controllers.txt im selben Verzeichnis wie config.txt. sdl_controllers.txt enthält eine Zuordnung pro Zeile.

Um eine benutzerdefinierte Zuordnungszeichenfolge für Ihren Controller zu generieren, verwenden Sie entweder das mit SDL2 mitgelieferte Programm „controllermap“ oder versuchen Sie es mit http://www.generalarcade.com/gamepadtool/

Um die ID Ihres Controllers herauszufinden, wie sie von SDL2 erkannt wird, suchen Sie nach „joysticks“ oder „Mapping“ in der Datei „log.txt“, nachdem Sie PICO-8 gestartet haben. Diese ID kann je nach Betriebssystem variieren. Siehe: https://www.lexaloffle.com/bbs/?tid=32130

Um festzulegen, welche Tastaturtasten Joystick-Tastenanschläge auslösen, verwenden Sie KEYCONFIG.

1.9 Screenshots und GIFs

Während eine Kassette läuft, verwende:

STRG-6 Speichere einen Screenshot auf dem Desktop
STRG-7 Erfasse das Bild des Kassettenetiketts
STRG-8 Starte die Videoaufnahme
STRG-9 Speichere ein GIF-Video auf dem Desktop (standardmäßig 8 Sekunden)

Sie können jederzeit ein Video speichern (die Aufnahme läuft immer); STRG-8 setzt lediglich den Startpunkt des Videos zurück. Um mehr als 8 Sekunden aufzunehmen, verwenden Sie den Befehl CONFIG (maximal: 120)

CONFIG GIF_LEN 60

Wenn du möchtest, dass die Aufnahme jedes Mal zurückgesetzt wird (um eine nicht überlappende Sequenz zu erstellen), verwende:

CONFIG GIF_RESET_MODE 1

Das GIF-Format kann 30 fps nicht exakt wiedergeben, daher verwendet PICO-8 stattdessen den nächstgelegenen Wert: 33,3 fps.

Wenn du Probleme beim Speichern auf dem Desktop hast, versuche, in der Datei config.txt einen alternativen Desktop-Pfad zu konfigurieren

1. Teile die .p8- oder .p8.png-Datei direkt mit anderen PICO-8-Nutzern

2. Veröffentlichen Sie die Cartridge im Lexaloffe BBS, um eine im Web spielbare Version zu erhalten

http://www.lexaloffle.com/pico-8.php?page=submit

1.11 SPLORE

SPLORE ist ein integriertes Dienstprogramm zum Durchsuchen und Organisieren sowohl lokaler als auch BBS- (Online-)Kassetten. Geben Sie SPLORE [Enter] ein, um es zu starten, oder starten Sie PICO-8 mit -splore.

Es ist möglich, SPLORE vollständig mit einem Joystick zu steuern:

LINKS und RECHTS, um durch die Cartridge-Listen zu navigieren
OBEN und UNTEN, um Elemente in jeder Liste auszuwählen
X, O oder MENU, um die Cartridge zu starten

Drücke innerhalb einer Cartridge MENU, um sie als Favorit zu speichern, oder drücke Exit, um zu SPLORE zurückzukehren. Wenn du eine Tastatur verwendest, kannst du auch F drücken, um ein Element als Favorit zu speichern, während es in der Cartridge-Listenansicht ausgewählt ist.

Wenn du eine Liste von BBS-Kassetten anzeigst, verwende den obersten Listeneintrag, um eine Liste der Kassetten erneut herunterzuladen. Wenn du offline bist, wird die zuletzt heruntergeladene Liste angezeigt, und es ist weiterhin möglich, alle Kassetten zu spielen, die du dir angesehen hast.

Sobald BBS-Kassetten ausgeführt oder in Splore aufgelistet wurden, werden sie automatisch abgerufen und dauerhaft zwischengespeichert. Es ist in der Regel nicht erforderlich, sie manuell herunterzuladen und zu speichern. Eine Ausnahme bilden Kassetten, die andere Kassetten laden (load()); für das erste Laden jeder Kassette ist eine Internetverbindung erforderlich.

Wenn du PICO-8 auf einem Rechner ohne Internetzugang installiert hast, kannst du auch INSTALL_GAMES verwenden, um eine kleine Auswahl vorinstallierter BBS-Kassetten zu /games hinzuzufügen. Es ist auch möglich, alle zwischengespeicherten Kassetten (sortiert nach Download-Zeit) über die Registerkarte „Lokale Dateien“ anzuzeigen.

Die Splore-Suchleiste kann nur mit einem Controller bedient werden; drücke LINKS und RECHTS, um den Cursor zu bewegen, und OBEN und UNTEN, um durch Buchstaben, Zahlen und einige Symbole zu blättern.

Um deine Online-BBS-Favoriten anzuzeigen, stelle sie auf „öffentlich“ (in deinen Kontoeinstellungen) und suche dann in Splore nach „fav:Benutzername“.

❷ Bearbeitungswerkzeuge

Drücke ESC, um zwischen Konsole und Editor umzuschalten.
Klicke oben rechts auf die Registerkarten des Bearbeitungsmodus, um zu wechseln, oder drücke ALT+LINKS/RECHTS.

2.1 Code-Editor

Halten Sie die Umschalttaste gedrückt, um auszuwählen (oder klicken und ziehen Sie mit der Maus)
STRG-X, C, V zum Ausschneiden, Kopieren oder Einfügen der Auswahl
STRG-Z, Y zum Rückgängigmachen und Wiederherstellen
STRG-F zum Suchen nach Text im aktuellen Tab
STRG-G zum Wiederholen der letzten Suche
STRG-L zum Springen zu einer Zeilennummer
STRG-PFEIL NACH OBEN, UNTEN, um zum Anfang oder Ende zu springen
ALT-PFEIL NACH OBEN, UNTEN, um zur vorherigen bzw. nächsten Funktion zu navigieren
STRG-PFEIL NACH LINKS, RECHTS, um wortweise zu springen
STRG-W, E, um zum Anfang oder Ende der aktuellen Zeile zu springen
STRG-D, um die aktuelle Zeile zu duplizieren
TAB, um eine Auswahl einzurücken (Umschalt, um die Einrückung aufzuheben)
STRG-B, um den ausgewählten Block zu kommentieren/den Kommentar aufzuheben
STRG-U, um Hilfe zum Schlüsselwort unter dem Cursor zu erhalten

Um Sonderzeichen einzugeben, die Tasten (und andere Glyphen) darstellen, verwende UMSCHALT-L,R,U,D,O,X Es gibt 3 zusätzliche Eingabemodi für Schriftzeichen, die umgeschaltet werden können:

STRG-J Hiragana // gib die entsprechenden Romaji-Zeichen ein (ka, ki, ku..)
STRG-K Katakana // + Umschalt-0..9 für zusätzliche Symbole
STRG-P Puny-Schriftart // halte die Umschalttaste gedrückt für die Standardschriftart

ⓘ

Standardmäßig werden Puny-Zeichen beim Kopieren/Einfügen als Unicode-Ersetzungen kodiert , und sowohl Groß- als auch Kleinbuchstaben im ASCII-Zeichensatz werden als reguläre PICO-8-Zeichen eingefügt. Um Puny-Zeichen als ASCII-Großbuchstaben zu kopieren/einzufügen, stelle sicher, dass der Puny-Modus (STRG-P) aktiviert ist.

■ Code-Registerkarten

Klicken Sie oben auf die Schaltfläche [+], um eine neue Registerkarte hinzuzufügen. Wechseln Sie zwischen den Registerkarten mit einem Linksklick oder mit STRG-TAB, UMSCHALT-STRG-TAB. Um die letzte Registerkarte zu entfernen, löschen Sie den Inhalt und wechseln Sie dann von ihr weg (STRG-A, ENTF, STRG-TAB)

Beim Ausführen eines Cartridges wird ein einziges Programm generiert, indem alle Registerkarten der Reihe nach verkettet werden.

■ Code-Beschränkungen

Die Anzahl der Code-Token wird unten rechts angezeigt. Ein Programm kann maximal 8192 Token enthalten. Jedes Token ist ein Wort (z. B. Variablenname) oder ein Operator. Klammerpaare und Zeichenfolgen zählen jeweils als 1 Token. Kommas, Punkte, LOCALs, Semikolons, ENDs und Kommentare werden nicht gezählt.

Klicke mit der rechten Maustaste, um zwischen anderen Statistiken zu wechseln (Zeichenanzahl, komprimierte Größe). Wenn eine Grenze erreicht ist, blinkt eine Warnleuchte. Dies kann durch einen Rechtsklick deaktiviert werden.

2.2 Sprite-Editor

Der Sprite-Editor ist sowohl für die Bearbeitung auf Sprite-Ebene als auch für die freie Bearbeitung auf Pixelebene ausgelegt. Der Sprite-Navigator am unteren Bildschirmrand bietet eine 8x8-Ansicht auf Sprite-Ebene des Sprite-Sheets , es ist jedoch möglich, Freiform-Werkzeuge (Verschieben, Auswählen) zu verwenden, wenn es um größere oder ungewöhnlich geformte Bereiche geht.

■ Zeichenwerkzeug

Klicken und ziehen Sie auf dem Sprite, um Pixel zu zeichnen, oder verwenden Sie die rechte Maustaste, um die Farbe unter dem Cursor auszuwählen.

Alle Vorgänge gelten nur für den sichtbaren Bereich oder den Ausschnitt, falls vorhanden.

Halten Sie die STRG-Taste gedrückt, um eine Farbe zu suchen und zu ersetzen.

■ Stempel-Werkzeug

Klicken Sie, um den Inhalt des Zwischenablagebereichs zu stempeln. Halten Sie die STRG-Taste gedrückt, um die Farbe 0 (Schwarz) als transparent zu behandeln.

■ Auswahlwerkzeug (Tastenkombination: UMSCHALT oder S)

Klicke und ziehe, um eine rechteckige Auswahl zu erstellen. Um die Auswahl aufzuheben, drücke die Eingabetaste oder klicke auf eine beliebige Stelle.

Wenn keine pixelweise Auswahl vorliegt, werden viele Operationen stattdessen auf eine spriteweise Auswahl oder die sichtbare Ansicht angewendet. Um Sprites auszuwählen, ziehe mit gedrückter Umschalttaste im Sprite-Navigator. Um das Sprite-Sheet auszuwählen, drücke STRG-A (wiederhole dies, um die untere Hälfte, die mit Kartendaten geteilt wird, auszublenden)

■ Verschiebungswerkzeug (Tastenkombination: LEERTASTE)

Klicken und ziehen Sie, um sich auf dem Sprite-Sheet zu bewegen.

■ Füllwerkzeug

Mit der aktuellen Farbe füllen. Dies gilt nur für die aktuelle Auswahl oder, falls keine Auswahl vorhanden ist, für den sichtbaren Bereich.

■ Formwerkzeuge

Klicken Sie auf die Werkzeugschaltfläche, um zwischen den Optionen „Oval“, „Rechteck“ und „Linie“ zu wechseln.

Halten Sie die STRG-Taste gedrückt, um ein gefülltes Oval oder Rechteck zu erhalten.
Halten Sie die UMSCHALT-Taste gedrückt, um an Kreisen, Quadraten oder Linien mit einem niedrigen Seitenverhältnis auszurichten.

■ Zusatztasten

STRG-Z:   Rückgängig
STRG-C/X: Ausgewählten Bereich oder ausgewählte Sprites kopieren/ausschneiden
STRG-V:   An der aktuellen Sprite-Position einfügen
Q/A,W/Z:  Zum vorherigen/nächsten Sprite wechseln
1,2:      Zur vorherigen/nächsten Farbe wechseln
TAB:      Vollbildansicht umschalten
Mausrad oder < und > zum Zoomen (zentriert im Vollbildmodus)

■ Sprite-Flags

Die 8 farbigen Kreise sind Sprite-Flags für das aktuelle Sprite. Diese haben keine besondere Bedeutung, können aber über die Funktionen FGET() / FSET() abgerufen werden. Sie sind von links beginnend ab 0 indiziert.

Weitere Informationen finden Sie unter FSET().

■ Laden von .png-Dateien in das Sprite-Sheet

Um eine PNG-Datei beliebiger Größe in das Sprite-Sheet zu laden, wähle zunächst das Sprite aus, das als Ziel für die obere linke Ecke dienen soll, und gib dann entweder „IMPORT IMAGE_FILE.PNG“ ein oder ziehe die Bilddatei per Drag & Drop in das PICO-8-Fenster. In beiden Fällen wird das Bild farblich an die aktuelle Anzeige-Palette angepasst.

2.3 Karteneditor

Die PICO-8-Karte ist ein 128x32 (oder 128x64 bei gemeinsamer Nutzung des Speicherplatzes) Block aus 8-Bit-Werten. Jeder Wert wird im Editor als Verweis auf ein Sprite (0..255) angezeigt, aber du kannst die Daten natürlich nutzen, um alles darzustellen, was du möchtest.

ⓘ

WARNUNG: Die zweite Hälfte des Sprite-Sheets (Bänke 2 und 3) und die untere Hälfte der Karte teilen sich denselben Speicherplatz auf der Kassette. Es liegt an dir, wie du die Daten verwendest, aber beachte, dass das Zeichnen auf der zweiten Hälfte des Sprite-Sheets Daten auf der Karte überschreiben könnte und umgekehrt.

Die Werkzeuge ähneln denen im Sprite-Bearbeitungsmodus. Wähle ein Sprite aus und klicke und ziehe, um Werte in die Karte zu malen.

Um mehrere Sprites zu zeichnen, wähle sie im Sprite-Navigator mit Umschalt+Ziehen aus. Um einen Werteblock zu kopieren, verwende das Auswahlwerkzeug und anschließend das Stempelwerkzeug zum Einfügen. Um die Karte zu verschieben, verwende das Verschiebungswerkzeug oder halte die Leertaste Q,W, um zum vorherigen/nächsten Sprite zu wechseln. Mausrad oder < und > zum Zoomen (zentriert im Vollbildmodus). STRG-H zum Umschalten auf die Hex-Ansicht (zeigt Kachelwerte und Sprite-Index in Hexadezimal an).

Das Verschieben von Sprites im Sprite-Sheet, ohne die Verweise auf sie in der Karte zu unterbrechen, ist etwas knifflig, aber möglich:

1. Drücke die Eingabetaste, um die Kartenauswahl zu löschen
2. Wähle die Sprites aus, die du verschieben möchtest (während du dich noch in der Kartenansicht befindest), und drücke Strg-X
3. Wähle den Bereich der Karte aus, den du ändern möchtest (standardmäßig die obere Hälfte der Karte)
// Drücke zweimal Strg-A, um die gesamte Karte einschließlich des gemeinsamen Speichers auszuwählen
4. Wähle das Ziel-Sprite aus (ebenfalls noch in der Kartenansicht) und drücke Strg-V

// Hinweis: Dieser Vorgang ändert den Rückgängig-Verlauf sowohl für den Karten- als auch für den Sprite-Editor, aber
// PICO-8 versucht, diese nach Möglichkeit synchron zu halten. Andernfalls können Änderungen, die durch das Verschieben
// von Kartensprites verursacht wurden, durch manuelles Rückgängigmachen im Sprite-Editor rückgängig gemacht werden.

2.4 SFX-Editor

Es gibt 64 SFX („Soundeffekte“) in einer Kassette, die sowohl für Sound als auch für Musik verwendet werden.

Jedes SFX hat 32 Noten, und jede Note hat:
Eine Frequenz (C0..C5)
Ein Instrument (0..7)
Eine Lautstärke (0..7)
Einen Effekt (0..7)

Jedes SFX verfügt außerdem über folgende Eigenschaften:

  Eine Wiedergabegeschwindigkeit (SPD): die Anzahl der „Ticks“, für die jede Note gespielt wird.
    // Das bedeutet, dass 1 am schnellsten ist, 3 dreimal so langsam usw.

  Loop-Start und -Ende: dies ist der Notenindex, an dem die Schleife beginnt und endet
    // Die Schleife wird deaktiviert, wenn der Startindex >= Endindex ist

Wenn nur die erste der beiden Zahlen verwendet wird (und die zweite 0 ist), wird dies als die Anzahl der abzuspielenden Noten interpretiert. Dies ist normalerweise für Soundeffekte nicht erforderlich (Sie können die restlichen Noten einfach leer lassen), ist aber nützlich für die Steuerung der Musikwiedergabe.

Es gibt zwei Modi zum Bearbeiten/Anzeigen eines SFX: den Pitch-Modus (eher für Soundeffekte geeignet) und den Tracker-Modus (eher für Musik geeignet). Der Modus kann über die Schaltflächen oben links geändert oder mit der TAB-Taste umgeschaltet werden.

▨ Tonhöhenmodus

Klicke und ziehe im Tonhöhenbereich, um die Frequenz für jede Note festzulegen, wobei das aktuell ausgewählte Instrument (durch Farbe gekennzeichnet) verwendet wird.

Halte die Umschalttaste gedrückt, um nur das ausgewählte Instrument anzuwenden.
Halte die STRG-Taste gedrückt, um eingegebene Noten an die C-Moll-Pentatonik anzupassen.
Klicke mit der rechten Maustaste, um das Instrument dieser Note auszuwählen.

▨ Tracker-Modus

Jede Note zeigt an: Frequenz, Oktave, Instrument, Lautstärke, Effekt
Um eine Note einzugeben, verwende q2w3er5t6y7ui zsxdcvgbhnjm (klavierähnliche Tastenbelegung)
Halte die Umschalttaste gedrückt, während du eine Note eingibst, um sie um -1 Oktave bis +1 Oktave zu transponieren
Neue Noten erhalten die Werte des ausgewählten Instruments/Effekts
Um eine Note zu löschen, verwende die Rücktaste oder setze die Lautstärke auf 0

Klicken Sie und dann bei gedrückter Umschalttaste, um einen Bereich auszuwählen, der kopiert (STRG-C) und eingefügt (STRG-V) werden kann. Beachten Sie, dass nur die ausgewählten Attribute kopiert werden. Doppelklicken Sie, um alle Attribute einer einzelnen Note auszuwählen.

Navigation:
Bild auf/ab oder Strg-Bild auf/ab, um 4 Notizen nach oben oder unten zu springen
Pos1/Ende, um zur ersten oder letzten Notiz zu springen
Strg-Pfeil links/rechts, um zwischen den Spalten zu springen

▨ Steuerelemente für beide Modi

- + zum Navigieren im aktuellen SFX
< > zum Ändern der Geschwindigkeit. SPACE zum Abspielen/Stoppen
SHIFT-SPACE zum Abspielen ab dem aktuellen SFX-Viertel (Gruppe von 8 Noten)
A, um ein Looping-Sample abzuspielen
Links- oder Rechtsklick, um die SPD- oder LOOP-Werte zu erhöhen/verringern
  // Halte die Umschalttaste beim Klicken gedrückt, um den Wert um 4 zu erhöhen/verringern
  // Alternativ kannst du klicken und nach links/rechts oder oben/unten ziehen
Umschalt-Klick auf ein Instrument, einen Effekt oder die Lautstärke, um dies auf alle Noten anzuwenden.

▨ Effekte

0 keine
1 Slide          //  Gleite zur nächsten Note und Lautstärke
2 Vibrato        //  Variiere die Tonhöhe schnell innerhalb eines Vierteltons
3 Drop           //  Senke die Frequenz schnell auf sehr niedrige Werte
4 Fade-in        //  Steigere die Lautstärke von 0 an
5 fade out       //  Die Lautstärke auf 0 abklingen lassen
6 arpeggio fast  //  Gruppen von 4 Noten mit einer Geschwindigkeit von 4 durchlaufen
7 arpeggio slow  //  Gruppen von 4 Noten mit einer Geschwindigkeit von 8 durchlaufen

Wenn die SFX-Geschwindigkeit <= 8 ist, werden die Arpeggio-Geschwindigkeiten auf 2 und 4 halbiert

▨ Filter

Jedes SFX verfügt über 5 Filterschalter, auf die im Tracker-Modus zugegriffen werden kann:

NOIZ:      Erzeugt reines weißes Rauschen (gilt nur für Instrument 6)
BUZZ:      Verschiedene Veränderungen der Wellenform, um sie summender klingen zu lassen
DETUNE-1:  Verstimmt eine zweite Stimme, um einen flangerähnlichen Effekt zu erzeugen
DETUNE-2:  Verschiedene Stimmungen der zweiten Stimme, meist eine Oktave nach oben oder unten
REVERB:    Wendet ein Echo mit einer Verzögerung von 2 oder 4 Ticks an
DAMPEN:    Tiefpassfilter in 2 verschiedenen Stufen

Wenn BUZZ mit Instrument 6 verwendet wird und NOIZ ausgeschaltet ist, wird reines braunes Rauschen erzeugt.

2.5 Musik-Editor

Musik in PICO-8 wird durch eine Abfolge von „Patterns“ gesteuert. Jedes Pattern ist eine Liste aus 4 Zahlen, die angeben, welches SFX auf dem jeweiligen Kanal abgespielt wird.

▨ Ablaufsteuerung

Der Wiedergabeablauf kann über die 3 Schaltflächen oben rechts gesteuert werden.

Wenn ein Pattern abgespielt wurde, wird das nächste Pattern abgespielt, es sei denn:

- es sind keine Daten mehr zum Abspielen vorhanden (die Musik stoppt)
- für dieses Pattern ist ein STOP-Befehl gesetzt (die dritte Schaltfläche)
- ein LOOP-BACK-Befehl gesetzt ist (die zweite Schaltfläche); in diesem Fall sucht der Musikplayer
  rückwärts nach einem Pattern, für das der LOOP-START-Befehl gesetzt ist (die erste Schaltfläche),
  oder kehrt zu Pattern 0 zurück, wenn keines gefunden wird.

Wenn ein Pattern SFX-Elemente mit unterschiedlichen Geschwindigkeiten enthält, endet die Wiedergabe des Patterns, sobald der ganz links liegende, nicht in einer Schleife befindliche Kanal abgespielt wurde. Dies kann genutzt werden, um Drum-Beats im Double-Time-Rhythmus oder ungewöhnliche Polyrhythmen zu erzeugen.

Bei Taktarten wie 3/4, bei denen weniger als 32 Zeilen gespielt werden sollen, bevor zum nächsten Pattern gesprungen wird, kann die Länge eines SFX festgelegt werden, indem nur die erste Loop-Position angepasst und die zweite auf Null belassen wird. Dies wird im SFX-Editor als „LEN“ (für „Length“) anstelle von „LOOP“ angezeigt.

▨ Musik kopieren und einfügen

So wählen Sie einen Bereich von Musiktiteln aus: Klicken Sie einmal auf den ersten Titel im Musiktitel-Navigator, dann bei gedrückter Umschalttaste auf den letzten Titel. Ausgewählte Titel können mit STRG-C und STRG-V kopiert und eingefügt werden. Beim Einfügen in eine andere Cartridge wird auch der SFX, auf den jeder Titel verweist, eingefügt (möglicherweise mit einem anderen Index), sofern er noch nicht vorhanden ist.

▨ SFX-Instrumente

Zusätzlich zu den 8 integrierten Instrumenten können benutzerdefinierte Instrumente mithilfe der ersten 8 SFX definiert werden. Verwenden Sie die Umschaltfläche rechts neben den Instrumenten, um einen Index auszuwählen, der im Instrumentenkanal grün statt rosa angezeigt wird.

Wenn eine Note eines SFX-Instruments gespielt wird, löst dies im Wesentlichen das SFX aus, verändert jedoch die Attribute der Note:

  Die Tonhöhe wird relativ zu C2 hinzugefügt
  Die Lautstärke wird multipliziert
  Effekte werden zusätzlich zu den Effekten des SFX-Instruments angewendet
  Alle im SFX-Instrument aktivierten Filter werden für diese Note aktiviert

Beispielsweise könnte ein einfacher Tremolo-Effekt implementiert werden, indem ein Instrument in SFX 0 definiert wird, das schnell zwischen den Lautstärken 5 und 2 wechselt. Wenn man dieses Instrument zum Spielen einer Note verwendet, kann die Lautstärke wie gewohnt weiter verändert werden (über den Lautstärkenkanal oder mithilfe der Ein-/Ausblendeffekte ). Auf diese Weise können SFX-Instrumente verwendet werden, um Kombinationen aus detaillierten Änderungen von Lautstärke, Tonhöhe und Klangtextur zu steuern.

SFX-Instrumente werden nur neu getriggert, wenn sich die Tonhöhe ändert oder die vorherige Note eine Lautstärke von Null hat. Dies ist nützlich für Instrumente, die sich im Laufe der Zeit langsamer verändern. Zum Beispiel: eine Glocke, die allmählich ausklingt. Um dieses Verhalten umzukehren, kann Effekt 3 (normalerweise „Drop“) verwendet werden, wenn die Note getriggert wird. Alle anderen Effektwerte haben ihre übliche Bedeutung beim Triggern von SFX-Instrumenten.

▨ Wellenform-Instrumente

Wellenform-Instrumente funktionieren genauso wie SFX-Instrumente, bestehen jedoch aus einer benutzerdefinierten 64-Byte-Wellenform, die in einer Schleife abgespielt wird. Klicken Sie auf die Umschaltfläche für die Wellenform im SFX-Editor, um SFX 0..7 als Wellenform-Instrument zu verwenden . In diesem Modus können Samples mit der Maus gezeichnet werden.

▨ Skalenausrichtung

Wenn Sie Noten im Tonhöhenmodus zeichnen, halten Sie die STRG-Taste gedrückt, um an die derzeit definierte Tonleiter anzuschnappen. Standardmäßig ist dies die C-Moll-Pentatonik, die jedoch im Tonleiter-Editor-Modus angepasst werden kann. Unten rechts befindet sich ein kleines Tastatursymbol, um diese Funktion umzuschalten. Es gibt 2 Transponier-Schaltflächen, 1 Invertier-Schaltfläche und 3 Schaltflächen für voreingestellte Tonleitern:

Dim   Verminderte Septim-Tonleiter // Umkehren, um eine Ganz-Halb-Tonleiter zu erhalten
Maj   Dur-Tonleiter                // Umkehren, um eine Pentatonik zu erhalten
Who   Ganztonleiter                // Umkehren, um … die andere Ganztonleiter zu erhalten

Das Ändern der Tonleiter hat keinen Einfluss auf den aktuellen SFX; die Tonleiter wird nur angewendet, wenn neue Noten bei gedrückter STRG-Taste gezeichnet werden.

❸ Exporter / Importer

Mit dem Befehl EXPORT können PNG- und WAV-Dateien sowie eigenständige HTML- und native Binär-Cartridge-Anwendungen erstellt werden. Das Ausgabeformat wird aus der Dateiendung abgeleitet (z. B. .png).

Es steht Ihnen frei, exportierte Cartridges und Daten nach Belieben zu verbreiten und zu nutzen, vorausgesetzt, Sie haben die Erlaubnis des Cartridge-Autors und der Mitwirkenden.

▨ Sprite-Sheet / Label (.png)

> IMPORT BLAH.PNG -- ERWARTET EINE 128X128-PNG-DATEI, DEREN FARBEN ZUR PICO-8-PALETTE PASSEN
> EXPORT BLAH.PNG -- VERWENDE DEN BEFEHL „FOLDER“, UM DIE EXPORTIERTE PNG-DATEI ZU FINDEN

Beim Importieren können die Schalter -x und -y verwendet werden, um die Zielposition in Pixeln anzugeben: Mit -s kann das Bild verkleinert werden (3 bedeutet eine Skalierung von 384x384 -> 128x128)

> IMPORT BLAH.PNG -X 16 -Y 16 -S 3

Verwenden Sie den Schalter -l mit IMPORT und EXPORT, um stattdessen vom Etikett der Kassette zu lesen und zu schreiben:

> IMPORT -L BLAH.PNG

ⓘ

Beim Importieren von Spritesheets oder Etiketten wird die Palette farblich an die aktuelle Zeichenpalette angepasst.

▨ SFX und Musik (.wav)

So exportierst du Musik aus dem aktuellen Pattern (wenn der Editor-Modus auf MUSIC steht) oder die aktuellen SFX:

> EXPORT FOO.WAV

So exportierst du alle SFXs als foo0.wav, foo1.wav .. foo63.wav:

> EXPORT FOO%D.WAV

▨ MAP und CODE

Eine Cartridge-Map oder ein Quellcode kann als einzelnes Bild mit dem Namen .map.png oder .lua.png exportiert werden:

> EXPORT FOO.MAP.PNG
> EXPORT FOO.LUA.PNG

Kartenbilder haben eine Größe von 1024x512 (128x32 8x8-Sprites). Lua-Bilder werden an die Größe angepasst, jedoch ist jede Zeile auf eine Breite von 192 Pixel festgelegt (und beschnitten).

▨ Cartridges (.p8, .p8.png, .p8.rom)

Das Speichern einer Cartridge mit EXPORT entspricht der Verwendung von SAVE, jedoch ohne die aktuell bearbeitete Cartridge zu ändern. Dies kann beispielsweise nützlich sein, um eine Kopie im .p8.png-Format zur Weitergabe zu speichern, ohne versehentlich weiterhin Änderungen an dieser Datei statt an der ursprünglichen .p8-Datei vorzunehmen.

„EXPORT“ kann auch verwendet werden, um Konvertierungen des Cartridge-Dateiformats über die Befehlszeile durchzuführen. Zum Beispiel in einer Linux-Shell:

> pico8 foo.p8 -export foo.p8.png

3.1 Webanwendungen (.html)

So generieren Sie einen eigenständigen HTML-Player (mygame.html, mygame.js):

> EXPORT MYGAME.HTML

Oder nur die .js-Datei:

> EXPORT MYGAME.JS

Verwenden Sie -f, um die Dateien in einen Ordner namens mygame_html zu schreiben, wobei index.html anstelle von mygame.html verwendet wird

> EXPORT -F MYGAME.HTML

Optional kannst du mit dem Schalter -p eine benutzerdefinierte HTML-Vorlage angeben:

> EXPORT MYGAME.HTML -P ONE_BUTTON

Dadurch wird die Datei {application data}/pico-8/plates/one_button.html als HTML-Shell verwendet, wobei eine spezielle Zeichenfolge „##js_file##“ (ohne Anführungszeichen) durch den .js-Dateinamen ersetzt wird und optional die Zeichenfolge „##label_file##“ durch das Label-Bild des Cartridges als Daten-URL ersetzt wird.

Verwenden Sie -w, um als .wasm + .js zu exportieren:

> EXPORT -W MYGAME.HTML

ⓘ

Beim Export als .wasm muss die Seite von einem Webserver bereitgestellt werden, anstatt sie einfach direkt aus dem lokalen Dateisystem in einem Browser zu öffnen. Für die meisten Zwecke ist der Standard-Export als .js ausreichend, aber .wasm ist etwas kleiner und schneller.

3.2 Binäre Anwendungen (.bin)

So generieren Sie eigenständige ausführbare Dateien für Windows, Linux (64-Bit), Mac und Raspberry Pi:

> EXPORT MYGAME.BIN

Standardmäßig wird das Cartridge-Label als Symbol ohne Transparenz verwendet. Um ein Symbol aus dem Sprite-Sheet anzugeben, verwenden Sie -i und optional -s und/oder -c , um Größe und Transparenz zu steuern.

-I N  Symbolindex N mit einer standardmäßigen transparenten Farbe von 0 (schwarz).
-S N  Größe NxN-Sprites. Die Größe 3 würde ein 24x24-Symbol erzeugen.
-C N  Farbe N als transparent behandeln. Verwenden Sie 16 für keine Transparenz.

Beispiel: Um ein 2x2-Sprite ab Index 32 im Sprite-Sheet zu verwenden und dabei die Farbe 12 als transparent zu behandeln:

> EXPORT -I 32 -S 2 -C 12 MYGAME.BIN

Um eine zusätzliche Datei in die Ausgabeordner und Archive aufzunehmen, verwende den Schalter -E:

> EXPORT -E README.TXT MYGAME.BIN

ⓘ

Windows-Dateisysteme unterstützen die Dateimetadaten nicht, die zum Erstellen einer ausführbaren Datei für Linux oder Mac erforderlich sind. PICO-8 umgeht dies, indem es ZIP-Dateien so exportiert, dass die Dateiattribute erhalten bleiben. Es wird daher empfohlen, die ausgegebenen ZIP-Dateien unverändert zu verteilen, um sicherzustellen, dass Benutzer auf anderen Betriebssystemen sie ausführen können. Andernfalls muss ein Linux-Benutzer, der die Binärdateien herunterlädt, möglicherweise den Befehl „chmod +x mygame“ auf die Datei anwenden, um sie auszuführen, und ein Mac-Benutzer müsste „chmod +x mygame.app/Contents/MacOS/mygame“

3.3 Hochladen auf itch.io

Wenn Sie Ihre exportierte Cartridge als spielbare HTML-Datei auf itch.io hochladen möchten:

1. In PICO-8: EXPORT -F MYGAME.HTML
2. Erstellen Sie ein neues Projekt über Ihr itch-Dashboard.
3. Komprimiere den Ordner und lade ihn hoch (setze „Diese Datei wird im Browser abgespielt“).
4. Binde ihn in die Seite ein, mit einer Größe von 750px x 680px.
5. Aktivieren Sie „Mobile Friendly“ (Standardausrichtung) und „Automatically start on page load“.
// Der Vollbild-Button ist nicht erforderlich, da die Standardvorlage von PICO-8 über einen eigenen verfügt.
6. Stellen Sie den Hintergrund (BG2) auf eine dunkle Farbe (z. B. #232323) und den Text auf eine helle Farbe (#cccccc) ein.

3.4 Exportieren mehrerer Cartridges

Bis zu 32 Cartridges können gebündelt werden, indem man sie an EXPORT übergibt, wenn man eigenständige HTML- oder native Binär-Player generiert.

> EXPORT MYGAME.HTML DAT1.P8 DAT2.P8 GAME2.P8

Während der Laufzeit kann auf die zusätzlichen Cartridges zugegriffen werden, als wären sie lokale Dateien:

RELOAD(0,0,0X2000, "DAT1.P8") -- SPRITESHEET AUS DAT1.P8 LADEN
LOAD("GAME2.P8")              -- EIN WEITERES MODUL LADEN UND AUSFÜHREN

ⓘ

Exportierte Cartridges können keine BBS-Cartridges laden und ausführen, z. B. über LOAD("#FOO")

3.5 Ausführen von EXPORT vom Host-Betriebssystem aus

Verwende den Schalter -export beim Starten von PICO-8, um den Exporter im Headless-Modus auszuführen. Dateipfade beziehen sich auf das aktuelle Verzeichnis und nicht auf das PICO-8-Dateisystem.

Parameter für den EXPORT-Befehl werden als einzelne Zeichenkette (in Kleinbuchstaben) übergeben:

pico8 mygame.p8 -export "-i 32 -s 2 -c 12 mygame.bin dat0.p8 dat1.p8"

▨ Typen und Zuweisung

Typen in Lua sind Zahlen, Zeichenketten, Boolesche Werte und Tabellen:

NUM = 12/100
S = "THIS IS A STRING"
B = FALSE
T = {1,2,3}

Zahlen in PICO-8 sind alle 16:16-Festkomma-Zahlen. Sie reichen von -32768,0 bis 32767,99999

Es kann die hexadezimale Notation mit optionalen Dezimalstellen verwendet werden:

?0x11 -- 17
?0x11.4000 -- 17,25

Dezimal geschriebene Zahlen werden auf den nächsten Festkommawert gerundet . Um die 32-Bit-Hexadezimal-Darstellung anzuzeigen, verwenden Sie PRINT(TOSTR(VAL,TRUE)):

?TOSTR(-32768,TRUE) -- 0x8000.0000
?TOSTR(32767.99999,TRUE) -- 0X7FFF.FFFF

Die Division durch Null ergibt 0x7fff.ffff, wenn sie positiv ist, oder -0x7fff.ffff, wenn sie negativ ist.

END

FOR X=1,10,3 DO PRINT(X) END -- 1,4,7,10

FOR X=5,1,-2 DO PRINT(X) END -- 5,3,1

▨ Funktionen und lokale Variablen

Variablen, die als LOCAL deklariert sind, gelten nur für den sie enthaltenden Codeblock (zum Beispiel innerhalb einer FUNCTION, einer FOR-Schleife oder einer IF THEN END-Anweisung ).

Y=0
FUNCTION PLUSONE(X)
  LOCAL Y = X+1
  RETURN Y
END
PRINT(PLUSONE(2)) -- 3
PRINT(Y) -- 0

▨ Tabellen

In Lua sind Tabellen eine Sammlung von Schlüssel-Wert-Paaren, bei denen die Typen von Schlüssel und Wert gemischt sein können. Sie können als Arrays verwendet werden, indem man sie mit Ganzzahlen indiziert.

A={} -- EINE LEERE TABELLE ERSTELLEN
A[1] = "BLAH"
A[2] = 42
A["FOO"] = {1,2,3}

Arrays verwenden standardmäßig eine 1-basierte Indizierung:

> A = {11,12,13,14}
> PRINT(A[2]) -- 12

Wenn Sie jedoch 0-basierte Arrays bevorzugen, schreiben Sie einfach etwas in den nullten Slot:

> A = {[0]=10,11,12,13,14}

Tabellen mit 1-basierten ganzzahligen Indizes sind jedoch ein Sonderfall. Die Länge eines solchen Arrays lässt sich mit dem Operator # ermitteln, und PICO-8 verwendet solche Arrays zur Implementierung der Funktionen ADD, DEL, DELI, ALL und FOREACH.

> PRINT(#A) -- 4
> ADD(A, 15)
> PRINT(#A) -- 5

Indizes, die Zeichenketten sind, können mit der Punktnotation geschrieben werden

PLAYER = {}
PLAYER.X = 2 -- entspricht PLAYER["X"]
PLAYER.Y = 3

Weitere Details findest du im Abschnitt „Tabellenfunktionen “.

▨ PICO-8-Kurzschreibweise

PICO-8 erlaubt auch mehrere nicht standardmäßige, kürzere Schreibweisen für gängige Muster.

1. IF THEN END-Anweisungen sowie WHILE THEN END können in einer einzigen Zeile wie folgt geschrieben werden:

IF (NOT B) I=1 J=2

Entspricht:

IF NOT B THEN I=1 J=2 END

Beachte, dass Klammern um die Kurzform der Bedingung erforderlich sind.

2. Zuweisungsoperatoren

Kurzform-Zuweisungsoperatoren können ebenfalls verwendet werden, wenn die gesamte Anweisung in einer Zeile steht. Sie können gebildet werden, indem ein '=' an einen beliebigen binären Operator angehängt wird, einschließlich arithmetischer (+=, -= ..), bitweiser (&=, |= ..) oder des Zeichenfolgenverkettungsoperators (..=)

A += 2   -- ENTSPRICHT: A = A + 2

3. !=-Operator

Keine Kurzform, aber PICO-8 akzeptiert auch != anstelle von ~= für „ungleich“

PRINT(1 != 2) -- TRUE
PRINT("FOO" == "FOO") -- TRUE (STRINGS WERDEN INTERN GESPEICHERT)

❺ PICO-8-Programmstruktur

Wenn ein PICO-8-Programm läuft, wird der gesamte Code aus den Registerkarten (von links nach rechts) verkettet und ausgeführt. Es ist möglich, eine eigene Hauptschleife manuell anzugeben, aber typischerweise verwenden PICO-8-Programme drei spezielle Funktionen, die, sofern sie vom Autor definiert wurden, während der Programmausführung aufgerufen werden:


_UPDATE() – Wird einmal pro Aktualisierung bei 30 fps aufgerufen.
_DRAW() -- Wird einmal pro sichtbarem Frame aufgerufen
_INIT() -- Wird einmal beim Programmstart aufgerufen.

Ein einfaches Programm, das alle drei verwendet, könnte so aussehen:

FUNCTION _INIT()
  -- IMMER AUF WEISS STARTEN
  COL = 7
END
 
FUNCTION _UPDATE()
  -- DRÜCKE X FÜR EINE ZUFÄLLIGE FARBE
  IF (BTNP(5)) COL = 8 + RND(8)
END
 
FUNKTION _DRAW()
  CLS(1)
  CIRCFILL(64,64,32,COL)
END

_DRAW() wird normalerweise mit 30 fps aufgerufen, aber wenn es nicht rechtzeitig fertig wird, versucht PICO-8, mit 15 fps zu laufen und ruft _UPDATE() zweimal pro sichtbarem Frame auf, um dies auszugleichen.

▨ PICO-8 mit 60 fps ausführen


_UPDATE60()

Wenn _UPDATE60() anstelle von _UPDATE() definiert ist, läuft PICO-8 im 60-fps-Modus:

- Sowohl _UPDATE60() als auch _DRAW() werden mit 60 fps aufgerufen
- Pro Frame steht die Hälfte der PICO-8-CPU zur Verfügung, bevor die Bildrate auf 30 fps sinkt

Beachte, dass nicht alle Host-Rechner in der Lage sind, mit 60 fps zu laufen. Ältere Rechner und/oder Webversionen können PICO-8 auch dazu veranlassen, mit 30 fps (oder 15 fps) zu laufen, selbst wenn die PICO-8-CPU nicht ausgelastet ist. In diesem Fall werden für jeden _DRAW-Aufruf mehrere _UPDATE60-Aufrufe auf die gleiche Weise ausgeführt.

▨ #INCLUDE

Quellcode kann beim Starten der Cartridge (jedoch nicht während der Laufzeit) mithilfe von „#INCLUDE FILENAME“ in ein Programm eingefügt werden, wobei FILENAME entweder eine Klartextdatei (mit Lua-Code), eine Registerkarte aus einer anderen Cartridge oder alle Registerkarten aus einer anderen Cartridge ist:

#INCLUDE SOMECODE.LUA
#INCLUDE ONETAB.P8:1
#INCLUDE ALLTABS.P8

Wenn die Cartridge ausgeführt wird, wird der Inhalt jeder eingebundenen Datei so behandelt, als wäre er anstelle dieser Zeile in den Editor eingefügt worden.

- Dateinamen sind relativ zur aktuellen Cartridge (d. h., sie müssen zuerst gespeichert werden)
- Einbindungen werden nicht rekursiv durchgeführt.
- Es gelten die üblichen Zeichen- und Token-Beschränkungen.

Wenn eine Cartridge als .P8.PNG gespeichert oder in eine Binärdatei exportiert wird, werden alle eingebundenen Dateien abgeflacht und mit der Cartridge gespeichert, sodass keine externen Abhängigkeiten bestehen.

#INCLUDE kann beispielsweise für folgende Zwecke verwendet werden:

- Gemeinsame Nutzung von Code zwischen Cartridges (Bibliotheken oder allgemeiner Multi-Cart-Code)
- Verwendung eines externen Code-Editors, ohne die .p8-Datei direkt bearbeiten zu müssen.
- Behandlung einer Cartridge als Datendatei, die von einem PICO-8-Bearbeitungstool geladen wird, um sie zu ändern.
- Laden und Speichern von Daten, die von einem externen (nicht-PICO-8-)Tool generiert wurden.

▨ Eigenheiten von PICO-8

Häufige Fallstricke, auf die man achten sollte:

- Die untere Hälfte des Sprite-Sheets und die untere Hälfte der Karte belegen denselben Speicher. // Verwende am besten nur das eine oder das andere, wenn du dir nicht sicher bist, wie das funktioniert.

- PICO-8-Zahlen haben eine begrenzte Genauigkeit und einen begrenzten Bereich; der kleinste Schritt zwischen den Zahlen beträgt etwa 0,00002 (0x0,0001), mit einem Bereich von -32768 (-0x8000) bis etwa 32767,99999 (0x7fff.ffff)
// Wenn Sie in jedem Frame 1 zu einem Zähler addieren, kommt es nach etwa 18 Minuten zu einem Überlauf!

- Lua-Arrays sind standardmäßig 1-basiert, nicht 0-basiert. FOREACH beginnt bei TBL[1], nicht bei TBL[0].

- COS() und SIN() nehmen Werte von 0 bis 1 anstelle von 0 bis PI*2 an, und SIN() ist invertiert.

- SGN(0) gibt 1 zurück.

▨ CPU

Obwohl PICO-8 keine klar definierte CPU hat, gibt es eine virtuelle CPU-Geschwindigkeit von 8 MHz, wobei jeder Lua-VM-Befehl etwa 2 Zyklen kostet. Auch integrierte Operationen wie das Zeichnen von Sprites verursachen CPU-Kosten. Das bedeutet, dass eine PICO-8-Cartridge, die auf einem Host-Rechner mit einer leistungsstarken CPU erstellt wurde, auch auf wesentlich langsameren Rechnern garantiert (ziemlich) gut läuft und auf Smartphones bzw. bei der Ausführung im Web nicht zu viel Akku verbraucht.

Um die CPU-Auslastung während der Ausführung einer Cartridge anzuzeigen, drücke STRG-P, um eine CPU-Anzeige ein- oder auszublenden, oder gib am Ende jedes Frames STAT(1) aus.

❻ API-Referenz

PICO-8 basiert auf der Programmiersprache Lua, enthält jedoch nicht die Lua-Standardbibliothek. Stattdessen wird eine kleine API angeboten, die dem minimalistischen Design und dem begrenzten Platz auf dem Bildschirm von PICO-8 entspricht. Ein Beispielprogramm, das die meisten API-Funktionen nutzt, finden Sie unter /DEMOS/API.P8

Funktionen werden hier wie folgt geschrieben:

FUNCTION_NAME(PARAMETER, [OPTIONAL_PARAMETER])

ⓘ

Beachten Sie, dass PICO-8 keine Groß- oder Kleinbuchstaben kennt – wenn Sie eine .p8- oder .lua-Datei direkt bearbeiten, sollten alle Funktionsnamen in Kleinbuchstaben geschrieben sein.

6.1 System

Systemfunktionen, die über die Befehlszeile aufgerufen werden, können auf die üblichen Klammern und Anführungszeichen verzichten. Anstelle von LOAD("BLAH.P8") ist es beispielsweise möglich, Folgendes zu schreiben:

>LOAD BLAH.P8


LOAD(FILENAME, [BREADCRUMB], [PARAM_STR])
SAVE(FILENAME)

Laden oder Speichern einer Cartridge

Beim Laden aus einer laufenden Cartridge wird die geladene Cartridge sofort mit der Parameterzeichenfolge PARAM_STR (abrufbar mit STAT(6)) ausgeführt, und es wird ein Menüpunkt mit dem Namen BREADCRUMB eingefügt, der den Benutzer zur vorherigen Cartridge zurückführt.

Dateinamen, die mit „#“ beginnen, werden als BBS-Cart-ID interpretiert, die sofort heruntergeladen und ausgeführt wird:

> LOAD("#MYGAME_LEVEL2", "BACK TO MAP", "LIVES="..LIVES)

Wenn die ID der übergeordnete Beitrag des Cartridges ist oder keine Revisionsnummer angegeben wurde, wird die neueste Version abgerufen. BBS-Cartridges können aus anderen BBS-Cartridges oder lokalen Cartridges geladen werden, jedoch nicht aus exportierten Cartridges.

Öffnen Sie den Cart-Ordner im Host-Betriebssystem.

Wenn LS von einer laufenden Cartridge aufgerufen wird, kann es nur lokal verwendet werden und gibt eine Tabelle mit den Ergebnissen zurück. Wenn LS von einer BBS-Cartridge aufgerufen wird, gibt es nil zurück.

Bei Verwendung einer benutzerdefinierten Hauptschleife ist jedoch normalerweise ein Aufruf von FLIP erforderlich:

6.2 Grafiken

PICO-8 verfügt über eine feste Kapazität von 128 8x8-Sprites sowie weitere 128, die sich mit der unteren Hälfte der Kartendaten überschneiden („gemeinsame Daten“). Diese 256 Sprites werden zusammen als Sprite-Sheet bezeichnet und können sich wie ein 128x128-Pixel-Bild vorstellen.

Alle Zeichenoperationen von PICO-8 unterliegen dem aktuellen Zeichenzustand . Der Zeichenzustand umfasst eine Kameraposition (zum Hinzufügen eines Offsets zu allen Koordinaten), Palettenzuordnung (zum Umfärben von Sprites), ein Beschneidungsrechteck, eine Zeichenfarbe und ein Füllmuster.

Der Zeichenzustand wird bei jedem Programmstart oder durch Aufruf von RESET() zurückgesetzt.

Farbindizes:
 
   0  schwarz   1  dunkelblau   2  dunkelviolett   3  dunkelgrün

Zeichnet ein in x und y symmetrisches Oval (eine Ellipse) mit dem angegebenen Begrenzungsrechteck.


LINE(X0, Y0, [X1, Y1, [COL]])

Zeichne eine Linie von (X0, Y0) nach (X1, Y1)

Wenn (X1, Y1) nicht angegeben sind, wird das Ende der zuletzt gezeichneten Linie verwendet.

LINE() ohne Parameter bedeutet, dass der nächste Aufruf von LINE(X1, Y1) nur die Endpunkte festlegt, ohne zu zeichnen.

CLS()
LINE()
FOR I=0,6 DO
  LINE(64+COS(I/6)*20, 64+SIN(I/6)*20, 8+I)
END


RECT(X0, Y0, X1, Y1, [COL])
RECTFILL(X0, Y0, X1, Y1, [COL])

Zeichne ein Rechteck oder ein gefülltes Rechteck mit den Eckpunkten (X0, Y0) und (X1, Y1).


RRECT(X, Y, W, H, R, [COL])
RRECTFILL(X, Y, W, H, R, [COL])

Zeichnet ein abgerundetes Rechteck oder ein gefülltes Rechteck mit abgerundeten Ecken.

Die Breite (W) und Höhe (H) sind in Pixeln angegeben und müssen beide größer als 0 sein, damit die Form gezeichnet wird.

Der Radius (R) ist standardmäßig 0 und entspricht der Größe des Viertelkreises, der an jeder Ecke gezeichnet werden soll. Der verwendete Radius wird so begrenzt, dass er im Bereich 0 .. min(Breite, Höhe)/2 liegt.

Zeichne ein rotes (Farbe 8) abgerundetes Rechteck mit einer Breite von 40 Pixeln und einer Höhe von 30 Pixeln, bei dem an jeder Ecke 3 Pixel fehlen (Radius 2):

> rrectfill(50,80,40,30,2,8)

Wenn die Bits 0x1800.0000 in COL gesetzt sind und (PEEK(0x5F34) & 2) == 2 ist, wird RRECTFILL invertiert gezeichnet.


PAL(C0, C1, [P])

PAL() tauscht die Farbe c0 gegen c1 für eine von drei Paletten-Neuzuordnungen (p ist standardmäßig 0):

0: Zeichnen-Palette

Die Zeichnen-Palette ordnet Farben neu zu, wenn sie gezeichnet werden. Beispielsweise kann ein orangefarbenes Blumen-Sprite als rote Blume gezeichnet werden, indem der 9. Palettenwert auf 8 gesetzt wird:

PAL(9,8)     -- nachfolgende orangefarbene (Farbe 9) Pixel werden als rot (Farbe 8) gezeichnet
SPR(1,70,60) -- alle orangefarbenen Pixel im Sprite werden stattdessen rot gezeichnet

Das Ändern der Zeichenpalette hat keine Auswirkungen auf bereits auf dem Bildschirm gezeichnete Elemente.

1: Anzeigepalette

Die Anzeigepalette ordnet den gesamten Bildschirm neu zu, wenn er am Ende eines Frames angezeigt wird. Wenn du beispielsweise PICO-8 startest und dann PAL(6,14,1) eingibst, siehst du, wie sich der gesamte graue (Farbe 6) Text sofort in Rosa (Farbe 14) ändert, obwohl er bereits gezeichnet wurde. Dies ist nützlich für bildschirmweite Effekte wie Ein- und Ausblenden.

2: Sekundäre Palette

Wird von FILLP() zum Zeichnen von Sprites verwendet. Dies bietet eine Zuordnung von einem einzelnen 4-Bit-Farbindex zu zwei 4-Bit-Farbindizes.

PAL() setzt alle Paletten auf die Systemstandardwerte zurück (einschließlich Transparenzwerte)
PAL(P) setzt eine bestimmte Palette (0..2) auf die Systemstandardwerte zurück


PAL(TBL, [P])

Wenn der erste Parameter von pal eine Tabelle ist, werden jedem Eintrag Farben zugewiesen. Um beispielsweise die Farben 12 und 14 auf Rot umzuordnen:

PAL({[12]=9, [14]=8})

Oder um den gesamten Bildschirm in Graustufen umzufärben (einschließlich aller bereits gezeichneten Elemente):

PAL({1,1,5,5,5,6,7,13,6,7,7,6,13,6,7,1}, 1)

Da Tabellenindizes bei 1 beginnen, wird in diesem Fall die Farbe 0 am Ende zugewiesen.


PALT(C, [T])

Transparenz für den Farbindex auf T (boolesch) setzen. Die Transparenz wird von SPR(), SSPR(), MAP() und TLINE() berücksichtigt

. PALT(8, TRUE) -- ROTE PIXEL WERDEN IN FOLGENDEN SPRITE-/TLINE-ZEICHNUNGSANRUFEN NICHT GEZEICHNET

PALT() setzt auf Standard zurück: alle Farben undurchsichtig außer Farbe 0

Wenn C der einzige Parameter ist, wird er als Bitfeld behandelt, das zum Setzen aller 16 Werte verwendet wird. Beispiel: Um die Farben 0 und 1 als transparent festzulegen:

PALT(0B1100000000000000)


SPR(N, X, Y, [W, H], [FLIP_X], [FLIP_Y])

Zeichne Sprite N (0..255) an der Position X,Y

W (Breite) und H (Höhe) sind standardmäßig 1, 1 und geben an, wie viele Sprites breit geblitzt werden sollen.

Farbe 0 wird standardmäßig transparent gezeichnet (siehe PALT())

Wenn FLIP_X TRUE ist, horizontal spiegeln.

Wenn FLIP_Y TRUE ist, vertikal spiegeln.


SSPR(SX, SY, SW, SH, DX, DY, [DW, DH], [FLIP_X], [FLIP_Y]]

Dehnt ein Rechteck des Sprite-Sheets (sx, sy, sw, sh) auf ein Zielrechteck auf dem Bildschirm (dx, dy, dw, dh) aus. In beiden Fällen sind die x- und y-Werte Koordinaten (in Pixeln) der oberen linken Ecke des Rechtecks mit einer Breite von w und einer Höhe von h.

Farbe 0 wird standardmäßig transparent gezeichnet (siehe PALT())

Wenn FLIP_X TRUE ist, wird horizontal gespiegelt.

Wenn FLIP_Y TRUE ist, wird vertikal gespiegelt.


FILLP(P)

Das PICO-8-Füllmuster ist ein 4x4-Muster aus 2-farbigen Kacheln, das von folgenden Funktionen verwendet wird: CIRC() CIRCFILL() RECT() RECTFILL() OVAL() OVALFILL() PSET() LINE()

P ist ein Bitfeld, das in Lesereihenfolge beginnend mit dem höchsten Bit interpretiert wird. Um den Wert von P für ein gewünschtes Muster zu berechnen, addiere die Bitwerte miteinander:

.-----------------------.
  |32768|16384| 8192| 4096|
  |-----|-----|-----|-----|
  | 2048| 1024| 512 | 256 |
  |-----|-----|-----|-----|
  | 128 |  64 |  32 |  16 |
  |-----|-----|-----|-----|
  |  8  |  4  |  2  |  1  |
  '-----------------------'

Beispielsweise würde FILLP(4+8+64+128+ 256+512+4096+8192) ein Schachbrettmuster erzeugen.

Dies lässt sich im Binärformat übersichtlicher ausdrücken: FILLP(0b0011001111001100).

Das Standard-Füllmuster ist 0, was bedeutet, dass eine einzige Volltonfarbe gezeichnet wird.

Um eine zweite Farbe für das Muster festzulegen, verwenden Sie die oberen Bits eines beliebigen Farbparameters:

FILLP(0b0011010101101000)
CIRCFILL(64,64,20, 0x4E) -- braun und rosa

Zusätzliche Einstellungen sind in den Bits 0b0.111 angegeben:

0b0.100 Transparenz

Wenn dieses Bit gesetzt ist, wird die zweite Farbe nicht gezeichnet

-- Schachbrettmuster mit transparenten Quadraten
FILLP(0b0011001111001100.1)

0b0.010 Auf Sprites anwenden

Wenn gesetzt, wird das Füllmuster auf Sprites (spr, sspr, map, tline) angewendet, wobei eine von der sekundären Palette bereitgestellte Farbabbildung verwendet wird.

Jeder Pixelwert im Sprite (nach wie vor nach Anwendung der Zeichenpalette) wird als Index in die Sekundärpalette übernommen. Jeder Eintrag in der Sekundärpalette enthält die beiden Farben, die zum Rendern des Füllmusters verwendet werden. Um beispielsweise ein weiß-rotes (7 und 8) Schachbrettmuster nur für blaue Pixel (Farbe 12) in einem Sprite zu zeichnen:

FOR I=0,15 DO PAL(I, I+I*16, 2) END -- alle anderen Farben werden auf sich selbst abgebildet
PAL(12, 0x87, 2) -- Farbe 12 in der Sekundärpalette neu zuordnen
 
FILLP(0b0011001111001100.01) -- Schachbrettmuster-Palette, auf Sprites angewendet
SPR(1, 64,64) -- Sprite zeichnen

0b0.001 Sekundäre Palette global anwenden

Wenn diese Option gesetzt ist, wird die Zuordnung der sekundären Palette auch von allen Zeichenfunktionen angewendet, die Füllmuster berücksichtigen (circfill, line usw.). Dies kann nützlich sein, wenn es in Verbindung mit Sprite-Zeichenfunktionen verwendet wird, sodass der Farbindex jedes Sprite-Pixels dasselbe bedeutet wie der Farbindex, der den Zeichenfunktionen übergeben wird.

FILLP(0b0011001111001100.001)
PAL(12, 0x87, 2)
CIRCFILL(64,64,20,12) -- rot-weiß karierter Kreis

Die Zuordnung der Sekundärpalette wird nach der regulären Zeichenpalettenzuordnung angewendet. Daher würde auch Folgendes einen rot-weiß karierten Kreis zeichnen:

PAL(3,12)
CIRCFILL(64,64,20,3)

Das Füllmuster kann auch durch Setzen von Bits in einem beliebigen Farbparameter festgelegt werden (zum Beispiel im Parameter von COLOR() oder im letzten Parameter von LINE(), RECT() usw.

POKE(0x5F34, 0x3) -- 0x1 aktiviert Füllmuster in den oberen Bits 0x2 aktiviert Inversionsmodus
CIRCFILL(64,64,20, 0x114E.ABCD) -- setzt das Füllmuster auf ABCD

Bei Verwendung des Farbparameters zur Einstellung des Füllmusters werden die folgenden Bits verwendet:

Bit 0x1000.0000 muss gesetzt sein: bedeutet „Bits 0xf00.ffff beachten“
Bit 0x0100.0000 Transparenz
Bit 0x0200.0000 auf Sprites anwenden
Bit 0x0400.0000 Sekundärpalette global anwenden
Bit 0x0800.0000 Zeichenvorgang umkehren (circfill/ovalfill/rectfill/rrectfill)
Bits 0x00FF.0000 sind die üblichen Farbbits
Bits 0x0000.FFFF werden als Füllmuster interpretiert

6.3 Tabellenfunktionen
⚠

Mit Ausnahme von PAIRS() gelten die folgenden Funktionen und der Operator # nur für Tabellen, die ab 1 indiziert sind und keine NIL-Einträge enthalten. Alle anderen Tabellenformen können als Hash-Maps oder Mengen betrachtet werden und nicht als Arrays mit einer bestimmten Länge.


ADD(TBL, VAL, [INDEX])

Fügt den Wert VAL am Ende der Tabelle TBL ein. Entspricht:

TBL[#TBL + 1] = VAL

Wenn ein Index angegeben wird, wird das Element an dieser Position eingefügt:

FOO={} -- LEERE TABELLE ERSTELLEN
ADD(FOO, 11)
ADD(FOO, 22)
PRINT(FOO[2]) -- 22


DEL(TBL, VAL)

Löscht die erste Instanz des Werts VAL in der Tabelle TBL. Die verbleibenden Einträge werden um einen Index nach links verschoben, um Lücken zu vermeiden.

Beachten Sie, dass VAL der Wert des zu löschenden Elements ist, nicht der Index in der Tabelle. (Um ein Element an einem bestimmten Index zu entfernen, verwenden Sie stattdessen DELI ). DEL gibt das gelöschte Element zurück oder gibt keinen Wert zurück, wenn nichts gelöscht wurde.

A={1,10,2,11,3,12}
FOR ITEM IN ALL(A) DO
  IF (ITEM < 10) THEN DEL(A, ITEM) END
END
FOREACH(A, PRINT) -- 10,11,12
PRINT(A[3]) -- 12


DELI(TBL, [I])

Wie DEL(), entfernt jedoch das Element mit dem Index I aus der Tabelle TBL. Wenn I nicht angegeben wird, wird das letzte Element der Tabelle entfernt und zurückgegeben.


COUNT(TBL, [VAL])

Gibt die Länge der Tabelle t zurück (entspricht #TBL). Wenn VAL angegeben wird, wird die Anzahl der Vorkommen von VAL in dieser Tabelle zurückgegeben.


ALL(TBL)

Wird in FOR-Schleifen verwendet, um alle Elemente einer Tabelle (die einen auf 1 basierenden ganzzahligen Index haben) in der Reihenfolge ihrer Hinzufügung zu durchlaufen.

T = {11,12,13}
ADD(T,14)
ADD(T,"HI")
FOR V IN ALL(T) DO PRINT(V) END -- 11 12 13 14 HI
PRINT(#T) -- 5


FOREACH(TBL, FUNC)

Rufe für jedes Element in der Tabelle TBL die Funktion FUNC mit dem Element als einzigem Parameter auf.

> FOREACH({1,2,3}, PRINT)


PAIRS(TBL)

Wird in FOR-Schleifen verwendet, um die Tabelle TBL zu durchlaufen, wobei sowohl der Schlüssel als auch der Wert für jedes Element bereitgestellt werden. Im Gegensatz zu ALL() durchläuft PAIRS() jedes Element unabhängig vom Indizierungsschema. Die Reihenfolge ist nicht garantiert.

T = {["HELLO"]=3, [10]="BLAH"}
T.BLUE = 5;
FOR K,V IN PAIRS(T) DO
  PRINT("K: "..K.."  V:"..V)
END

Ausgabe:

K: 10  v:BLAH
K: HELLO  v:3
K: BLUE  v:5

6.4 Eingabe
BTN([B], [PL])

Ruft den Status von Taste B für Spieler PL ab (Standardwert 0)

B: 0..5: links rechts oben unten button_o button_x
PL: Spielerindex 0..7

Anstelle einer Zahl für B kann auch ein Tastensymbol verwendet werden. (Im Coded-Editor: Shift-L R U D O X)

Wenn keine Parameter angegeben werden, gibt die Funktion ein Bitfeld mit allen 12 Tastenzuständen für Spieler 0 und 1 zurück // P0: Bits 0..5 P1: Bits 8..13

Standard-Tastaturbelegungen für Spielertasten:

Spieler 0: [DPAD]: Cursortasten, [O]: Z C N [X]: X V M
Spieler 1: [DPAD]: SFED, [O]: LSHIFT [X]: TAB W Q A

⚠

Obwohl PICO-8 alle Tastenkombinationen akzeptiert, beachte bitte, dass es auf einem physischen Game-Controller in der Regel nicht möglich ist, die Tasten LINKS und RECHTS gleichzeitig zu drücken. Bei einigen Controllern ist die Kombination NACH OBEN + LINKS/RECHTS ebenfalls umständlich, wenn [X] oder [O] anstelle von NACH OBEN verwendet werden könnten (z. B. zum Springen / Beschleunigen).


BTNP(B, [PL])

BTNP ist die Abkürzung für „Button Pressed“ (Taste gedrückt); anstatt „true“ zu sein, wenn eine Taste gedrückt gehalten wird, gibt BTNP „true“ zurück, wenn eine Taste gedrückt ist UND sie im letzten Frame nicht gedrückt war. Es wiederholt sich außerdem nach 15 Frames und gibt danach alle 4 Frames „true“ zurück (bei 30 fps – doppelt so oft bei 60 fps). Dies kann beispielsweise für die Menünavigation oder die rasterbasierte Bewegung des Spielers verwendet werden.

Der von BTNP ausgelesene Status wird zu Beginn jedes Aufrufs von _UPDATE oder _UPDATE60 zurückgesetzt, daher ist es vorzuziehen, BTNP innerhalb einer dieser Funktionen zu verwenden.

Benutzerdefinierte Verzögerungen (in Frames bei 30 fps ) können durch das Ansteuern der folgenden Speicheradressen eingestellt werden:

POKE(0X5F5C, DELAY) -- LEGT DIE ANFÄNGLICHE VERZÖGERUNG VOR DER WIEDERHOLUNG FEST. 255 BEDEUTET „NIEMALS WIEDERHOLEN“.
POKE(0X5F5D, DELAY) -- LEGT DIE WIEDERHOLUNGSVERZÖGERUNG FEST.

In beiden Fällen kann 0 für das Standardverhalten verwendet werden (Verzögerungen 15 und 4)

6.5 Audio
SFX(N, [CHANNEL], [OFFSET], [LENGTH])

Spielt den Soundeffekt N (0..63) auf dem Kanal CHANNEL (0..3) ab der Note OFFSET (0..31 in Noten) für die Dauer LENGTH Noten.

Die Verwendung negativer CHANNEL-Werte hat eine besondere Bedeutung:

CHANNEL -1: (Standard) wählt automatisch einen Kanal aus, der nicht verwendet wird
CHANNEL -2: stoppt die Wiedergabe des angegebenen Sounds auf allen Kanälen

N kann ein Befehl für den angegebenen CHANNEL sein (oder für alle Kanäle, wenn CHANNEL < 0):

N -1: Ton auf diesem Kanal stoppen
N -2: Ton auf diesem Kanal aus der Schleife entlassen

SFX(3)    --  SFX 3 ABSPIELEN
SFX(3,2)  --  SFX 3 AUF KANAL 2 ABSPIELEN
SFX(3,-2) --  SFX 3 AUF ALLEN KANÄLEN ANHALTEN
SFX(-1,2) --  ALLES ANHALTEN, WAS AUF KANAL 2 ABGESPIELT WIRD
SFX(-2,2) --  LOOP AUF KANAL 2 BEENDEN
SFX(-1)   --  ALLE TÖNE AUF ALLEN KANÄLEN BEENDEN
SFX(-2)   --  LOOP AUF ALLEN KANÄLEN BEENDEN


MUSIC(N, [FADE_LEN], [CHANNEL_MASK])

Musik ab Pattern N (0..63) abspielen
N -1, um die Musik zu stoppen

FADE_LEN wird in ms angegeben (Standard: 0). Um also Pattern 0 über 1 Sekunde einblenden zu lassen:

MUSIC(0, 1000)

CHANNEL_MASK legt fest, welche Kanäle ausschließlich für Musik reserviert werden sollen. Um beispielsweise nur auf den Kanälen 0..2 abzuspielen:

MUSIC(0, NIL, 7) -- 1 | 2 | 4

Reservierte Kanäle können weiterhin zum Abspielen von Soundeffekten verwendet werden, jedoch nur, wenn dieser Kanalindex explizit von SFX() angefordert wird.

6.6 Karte

Die PICO-8-Map ist ein 128x32-Raster aus 8-Bit-Werten oder 128x64 bei Verwendung des gemeinsamen Speichers. Bei Verwendung des Map-Editors wird die Bedeutung jedes Werts als Index in das Sprite-Sheet (0..255) interpretiert. Sie kann jedoch stattdessen auch als allgemeiner Datenblock verwendet werden.


MGET(X, Y)
MSET(X, Y, VAL)

Liest oder setzt den Kartenwert (VAL) an X,Y

Wenn X und Y außerhalb des Bereichs liegen, gibt MGET 0 zurück oder einen benutzerdefinierten Rückgabewert, der wie folgt festgelegt werden kann:

POKE(0x5f36, 0x10)
POKE(0x5f5a, NEWVAL)


MAP(TILE_X, TILE_Y, [SX, SY], [TILE_W, TILE_H], [LAYERS])

Zeichnet einen Ausschnitt der Karte (beginnend bei TILE_X, TILE_Y) an der Bildschirmposition SX, SY (Pixel).

Um einen 4x2-Block von Kacheln, beginnend bei 0,0 auf der Karte, auf dem Bildschirm bei 20,20 zu zeichnen:

MAP(0, 0, 20, 20, 4, 2)

TILE_W und TILE_H beziehen sich standardmäßig auf die gesamte Karte (einschließlich gemeinsam genutzter Bereiche, falls zutreffend).

MAP() wird oft in Verbindung mit CAMERA() verwendet. Um die Karte so zu zeichnen, dass ein Spielerobjekt (bei PL.X und PL.Y in Pixeln) zentriert ist:

CAMERA(PL.X - 64, PL.Y - 64)
MAP()

LAYERS ist ein Bitfeld. Wenn es angegeben wird, werden nur Sprites mit übereinstimmenden Sprite-Flags gezeichnet. Wenn LAYERS beispielsweise 0x5 ist, werden nur Sprites mit den Flags 0 und 2 gezeichnet.

Sprite 0 wird als „leer“ interpretiert und nicht gezeichnet. Um dieses Verhalten zu deaktivieren, verwende: POKE(0x5F36, 0x8)


TLINE(X0, Y0, X1, Y1, MX, MY, [MDX, MDY], [LAYERS])

Zeichnet eine texturierte Linie von (X0,Y0) nach (X1,Y1) und entnimmt dabei Farbwerte aus der Karte. Wenn LAYERS angegeben ist, werden nur Sprites mit passenden Flags gezeichnet (ähnlich wie bei MAP())

MX und MY sind die Kartenkoordinaten, aus denen die Werte entnommen werden sollen, angegeben in Kacheln. Die Farbwerte werden aus dem 8x8-Sprite entnommen, das sich auf jeder Kartenkachel befindet. Zum Beispiel:

2.0, 1.0 bedeutet die obere linke Ecke des Sprites an der Position 2,1 auf der Karte
2.5, 1.5 bedeutet Pixel (4,4) desselben Sprites

MDX, MDY sind Deltas, die nach dem Zeichnen jedes Pixels zu mx, my addiert werden. (Standardwert ist 0.125, 0)

Die Kartenkoordinaten (MX, MY) werden durch Werte maskiert, die berechnet werden, indem 0x0.0001 von den Werten an den Adressen 0x5F38 und 0x5F39 abgezogen wird. Einfacher ausgedrückt bedeutet dies, dass Sie einen Abschnitt der Karte in einer Schleife wiederholen können, indem Sie die Breite und Höhe eingeben, innerhalb derer die Schleife laufen soll, sofern es sich um Potenzen von 2 handelt (2, 4, 8, 16..)

Um beispielsweise alle 8 Kacheln horizontal und alle 4 Kacheln vertikal zu wiederholen:

POKE(0x5F38, 8)
POKE(0x5F39, 4)
TLINE(...)

Die Standardwerte (0,0) ergeben eine Maske von 0xff.ffff, was bedeutet, dass die Samples alle 256 Kacheln wiederholt werden.

Ein Offset für den Startpunkt der Samples (ebenfalls in Kacheln) kann auch an den Adressen 0x5f3a und 0x5f3b angegeben werden:

POKE(0x5F3A, OFFSET_X)
POKE(0x5F3B, OFFSET_Y)

Sprite 0 wird als „leer“ interpretiert und nicht gezeichnet. Um dieses Verhalten zu deaktivieren, verwende: POKE(0x5F36, 0x8)

■ Einstellung der TLINE-Genauigkeit

Standardmäßig werden TLINE-Koordinaten (mx, my, mdx, mdy) in Kacheln ausgedrückt. Das bedeutet, dass 1 Pixel 0,125 entspricht und nur 13 Bits für den Bruchteil verwendet werden. Wenn eine höhere Genauigkeit erforderlich ist, kann der Koordinatenraum angepasst werden, um mehr Bits für den Bruchteil zuzulassen. Dies kann nützlich sein, beispielsweise bei texturierten Wänden, wo der kumulierte Fehler aus der Rundung von mdx und mdy bei Nahaufnahme sichtbar werden kann.

Die Anzahl der Bits, die für den Bruchteil jedes Pixels verwendet werden, wird in einem speziellen Register gespeichert, das durch einmaligen Aufruf von TLINE mit einem einzigen Argument angepasst werden kann:

TLINE(16) -- MX,MY,MDX,MDY in Pixeln ausgedrückt

6.7 Speicher

PICO-8 verfügt über 3 Speichertypen:

1. Basis-RAM (64k): siehe Layout unten. Zugriff mit PEEK(), POKE(), MEMCPY(), MEMSET()
2. Cartridge-ROM (32k): gleiches Layout wie Basis-RAM bis 0x4300
3. Lua-RAM (2MB): kompiliertes Programm + Variablen

ⓘ


Technischer Hinweis: Während der Verwendung des Editors befinden sich die zu bearbeitenden Daten im Cart-ROM, aber API-Funktionen wie SPR() und SFX() wirken nur auf den Basis-RAM. PICO-8 kopiert das Cartridge-ROM automatisch in den Basis-RAM (d. h. ruft RELOAD() auf) in 3 Fällen:
1. Wenn ein Cartridge geladen wird
2. Wenn ein Cartridge ausgeführt wird
3. Beim Verlassen eines der Editor-Modi // kann mit poke(0x5f37,1) deaktiviert werden

■ Basis-RAM-Speicherlayout

0X0    GFX-
0X1000 GFX2/MAP2 (GEMEINSAM)
0X2000 MAP-
0X3000 GFX-FLAGS
0X3100 SONG-
0X3200 SFX-
0X4300 BENUTZERDATEN
0X5600 BENUTZERDEFINIERTE SCHRIFTART (FALLS DEFINIERT)
0X5E00 PERMANENTE CART-DATEN (256 BYTE)
0X5F00 ZEICHENSTATUS
0X5F40 HARDWARE-STATUS
0X5F80 GPIO-PINS (128 BYTE)
0X6000 SCREEN (8K)
0x8000 USER DATA

Benutzerdaten haben keine besondere Bedeutung und können über MEMCPY(), PEEK() und POKE() für beliebige Zwecke verwendet werden. Persistente Kartendaten werden auf 0x5e00..0x5eff abgebildet, aber nur gespeichert, wenn CARTDATA() aufgerufen wurde. Das Farbformat (gfx/screen) beträgt 2 Pixel pro Byte: Die unteren Bits codieren das linke Pixel jedes Paares. Das Kartenformat beträgt ein Byte pro Kachel, wobei jedes Byte normalerweise einen Sprite-Index codiert.

■ Neuzuordnung von Grafik- und Kartendaten

Die Speicherbereiche GFX, MAP und SCREEN können durch Setzen von Werten an den folgenden Adressen neu zugewiesen werden:

0X5F54 GFX:    kann 0x00 (Standard) oder 0x60 (Bildspeicher als Spritesheet verwenden) sein
0X5F55 SCREEN: kann 0x60 (Standard) oder 0x00 sein (Spritesheet als Bildschirmspeicher verwenden)
0X5F56 MAP:    kann 0x20 (Standard) oder 0x10..0x2f oder 0x80 und höher sein.
0X5F57 MAP SIZE: Kartenbreite. 0 bedeutet 256. Standardwert ist 128.

Adressen können in Schritten von 256 Byte angegeben werden. So bedeutet 0x20 0x2000, 0x21 bedeutet 0x2100 usw. Die Map-Adressen 0x30..0x3f werden als 0x10..0x1f (gemeinsamer Speicherbereich) interpretiert. Map-Daten können nur innerhalb der Speicherbereiche 0x1000..0x2fff, 0x8000..0xffff enthalten sein, und die Map-Höhe wird als die größtmögliche Größe bestimmt, die in den gegebenen Bereich passt.

GFX- und SCREEN-Adressen können zusätzlich auf die oberen Speicherplätze 0x80, 0xA0, 0xC0, 0xE0 abgebildet werden, mit der Einschränkung, dass sich MAP nicht mit dieser Adresse überschneiden darf (in diesem Fall werden die in Konflikt stehenden GFX- und/oder SCREEN-Zuordnungen auf ihre Standardzuordnung zurückgesetzt).

ⓘ

Die GFX- und SCREEN-Speicherzuordnung erfolgt auf einer niedrigen Ebene, was sich auch auf Speicherzugriffsfunktionen (peek, poke, memcpy) auswirkt. Die 8-KB-Speicherblöcke ab 0x0 und 0x6000 können als Zeiger auf einen separaten Videospeicher betrachtet werden, und das Setzen der Werte an 0x5F54 und 0x5F56 verändert diese Zeiger.

■ Bitweise Operationen

Bitweise Operationen ähneln logischen Ausdrücken, funktionieren jedoch auf Bit-Ebene.

Angenommen, Sie haben zwei Zahlen (hier in Binärform mit dem Präfix „0b“ geschrieben):

X = 0b1010
Y = 0b0110

Ein bitweises UND liefert Bits, die gesetzt sind, wenn die entsprechenden Bits in X und Y beide gesetzt sind

> PRINT(BAND(X,Y)) -- ERGEBNIS:0B0010 (2 IN DEZIMAL)

In PICO-8 stehen 9 bitweise Funktionen zur Verfügung:

BAND(X, Y) -- BEIDE BITS SIND SETZT
BOR(X, Y)  -- EINES DER BITS IST SETZT
BXOR(X, Y) -- EINES DER BITS IST SETZT, ABER NICHT BEIDE
BNOT(X)    -- KEIN BIT IST SETZT
SHL(X, N)  -- N BITS NACH LINKS VERSCHIEBEN (NULLEN WERDEN VON RECHTS EINGEFÜGT)
SHR(X, N)  -- ARITHMETISCHE RECHTSVERSCHIEBUNG (DER ZUSTAND DES ÄUSSERSTEN BITS WIRD KOPIERT)
LSHR(X, N) -- LOGISCHE RECHTSVERSCHIEBUNG (NULLEN WERDEN VON LINKS EINGEFÜGT)
ROTL(X, N) -- ALLE BITS IN X UM N STELLEN NACH LINKS DREHEN
ROTR(X, N) -- ALLE BITS IN X UM N STELLEN NACH RECHTS DREHEN

Es sind auch Operatorversionen verfügbar: & | ^^ ~ << >> >>> <<> >><

Beispiel: PRINT(67 & 63) -- Ergebnis: 3 entspricht BAND(67,63)

Operatoren sind etwas schneller als die entsprechenden Funktionen. Sie verhalten sich genau gleich, außer dass, wenn Operanden keine Zahlen sind, ein Laufzeitfehler auftritt (die Funktionsversionen setzen stattdessen standardmäßig den Wert 0).

6.9 Benutzerdefinierte Menüpunkte
MENUITEM(INDEX, [LABEL], [CALLBACK])

Fügt einen Eintrag zum Pausenmenü hinzu oder aktualisiert ihn.

INDEX sollte zwischen 1 und 5 liegen und bestimmt die Reihenfolge, in der die einzelnen Menüeinträge angezeigt werden.

LABEL sollte eine Zeichenkette mit einer Länge von bis zu 16 Zeichen sein

.

CALLBACK ist eine Funktion, die aufgerufen wird, wenn der Eintrag vom Benutzer ausgewählt wird. Wenn der Callback „true“ zurückgibt, bleibt das Pausenmenü geöffnet.

Wenn keine Bezeichnung oder Funktion angegeben wird, wird der Menüpunkt entfernt.

MENUITEM(1, "RESTART PUZZLE",
  FUNCTION() RESET_PUZZLE() SFX(10) END
)

Der Callback nimmt ein einziges Argument entgegen, das ein Bitfeld der Tasten L, R und X darstellt.

MENUITEM(1, „FOO“,
  FUNCTION(B) IF (B&1 > 0) THEN PRINTH(„LEFT WAS PRESSED“) END END
)

Um Tastendrücke zu filtern, die den Callback auslösen können, kann eine Maske in den Bits 0xff00 von INDEX angegeben werden. Um beispielsweise L und R für einen bestimmten Menüpunkt zu deaktivieren, setzen Sie die Bits 0x300 im Index:

MENUITEM(2 | 0x300, „RESET PROGRESS“,
  FUNCTION() DSET(0,0) END
)

Menüelemente können innerhalb von Callbacks aktualisiert, hinzugefügt oder entfernt werden:

MENUITEM(3, „SCREENSHAKE: OFF“,
  FUNCTION()
    SCREENSHAKE = NOT SCREENSHAKE
    MENUITEM(NIL, "SCREENSHAKE: "..(SCREENSHAKE AND "ON" OR "OFF"))
    RETURN TRUE -- DON'T CLOSE
  END
)

Zeichenketten in Lua werden entweder in einfache oder doppelte Anführungszeichen gesetzt oder mit passenden [[ ]]-Klammern geschrieben:

Bei Verwendung als Teil eines arithmetischen Ausdrucks werden Zeichenfolgenwerte in Zahlen umgewandelt:

Konvertiert VAL in eine Zeichenkette.

FORMAT_FLAGS ist ein Bitfeld:

0x1: Gibt den rohen Hexadezimalwert von Zahlen, Funktionen oder Tabellen aus.
0x2: Gibt VAL als vorzeichenbehaftete 32-Bit-Ganzzahl aus, indem es um 16 Bit nach links verschoben wird.

TOSTR(17,0x3) -- "0x00110000"

Konvertiert VAL in eine Zahl.

TONUM("17.5") -- 17.5

TONUM("HOGE") -- KEIN RÜCKGABEWERT

FORMAT_FLAGS ist ein Bitfeld:

0x1: Liest die Zeichenkette als (vorzeichenlose, ganzzahlige) Hexadezimalzahl ohne das Präfix „0x“ ein
Nicht-hexadezimale Zeichen werden als „0“ interpretiert.
  0x2: Die Zeichenkette als vorzeichenbehaftete 32-Bit-Ganzzahl lesen und um 16 Bit nach rechts verschieben.
0x4: Wenn VAL nicht in eine Zahl konvertiert werden kann, 0 zurückgeben

TONUM("1114112", 0x2) -- 17
TONUM("1234abcd", 0x3) -- 0x1234.abcd

Konvertiert einen oder mehrere ordinäre Zeichencodes in eine Zeichenkette.

CHR(64) -- "@"
CHR(104,101,108,108,111) -- "hello"

Konvertiert ein oder mehrere Zeichen aus der Zeichenkette STR in ihre ordinalen (0..255) Zeichencodes.

Verwenden Sie den Parameter INDEX, um anzugeben, welches Zeichen in der Zeichenkette verwendet werden soll. Wenn INDEX außerhalb des Bereichs liegt oder str keine Zeichenkette ist, gibt ORD nil zurück.

Extrahiert eine Teilzeichenfolge aus der Zeichenkette str, beginnend bei pos0 bis einschließlich pos1. Wenn POS1 nicht angegeben ist, wird der Rest der Zeichenkette zurückgegeben. Wenn POS1 angegeben ist, aber keine Zahl ist, wird ein einzelnes Zeichen an POS0 zurückgegeben.

Leere Elemente werden als leere Zeichenketten gespeichert.

6.11 Cartridge-Daten

Mit CARTDATA(), DSET() und DGET() können 64 Zahlen (256 Bytes) an persistenten Daten auf dem PICO-8 des Benutzers gespeichert werden, die auch nach dem Entladen der Cartridge oder dem Herunterfahren von PICO-8 erhalten bleiben. Dies kann als einfache Möglichkeit genutzt werden, um beispielsweise Highscores oder den Spielfortschritt zu speichern. Es kann auch genutzt werden, um Daten zwischen Kassetten / Kassettenversionen auszutauschen.

Wenn mehr als 256 Bytes benötigt werden, ist es auch möglich, mit CSTORE() direkt auf die Kassette zu schreiben. Der Nachteil ist, dass die Daten an diese bestimmte Version der Kassette gebunden sind. Wenn beispielsweise ein Spiel aktualisiert wird, verlieren die Spieler ihre Spielstände. Außerdem muss in den Datenbereichen der Kassette etwas Speicherplatz als Speicherplatz freigehalten werden.

Eine weitere Alternative besteht darin, durch Angabe eines vierten Parameters bei CSTORE() direkt auf eine zweite Kassette zu schreiben. Dies erfordert einen Kassettenwechsel (was in der Praxis lediglich bedeutet, dass der Benutzer 1 Sekunde lang eine sich drehende Kassettenanimation sehen muss).

CSTORE(0,0,0X2000, "SPRITE SHEET.P8")
-- SPÄTER DIE GESPEICHERTEN DATEN WIEDERHERSTELLEN:
RELOAD(0,0,0X2000, "SPRITE SHEET.P8")


CARTDATA(ID)

Öffnet einen permanenten Datenspeicherplatz, der durch eine ID indiziert ist und zum Speichern und Abrufen von bis zu 256 Byte (64 Zahlen) an Daten mit DSET() und DGET() verwendet werden kann.

CARTDATA("ZEP_DARK_FOREST")
DSET(0, SCORE)

Die ID ist eine Zeichenkette mit einer Länge von bis zu 64 Zeichen und sollte so ungewöhnlich sein, dass andere Cartridges nicht versehentlich dieselbe ID verwenden. Zulässige Zeichen sind a..z, 0..9 und der Unterstrich (_)

Gibt „true“ zurück, wenn Daten geladen wurden, andernfalls „false“.

CARTDATA kann einmal pro Cartridge-Ausführung aufgerufen werden, daher kann nur ein einziger Datenspeicherplatz verwendet werden.

Sobald eine Cartdata-ID festgelegt wurde, wird der Speicherbereich 0X5E00..0X5EFF auf den permanenten Speicher abgebildet und kann entweder direkt oder über DGET()/@DSET() angesprochen werden.

Es ist nicht erforderlich, geschriebene Daten zu flushen – sie werden automatisch im permanenten Speicher gespeichert, selbst wenn sie durch direktes POKE() auf 0X5E00..0X5EFF geändert werden.


DGET(INDEX)

Ruft die unter INDEX (0..63) gespeicherte Zahl ab

Verwenden Sie dies erst, nachdem Sie CARTDATA() aufgerufen haben


DSET(INDEX, VALUE)

Setzt die unter INDEX (0..63) gespeicherte Zahl

Verwenden Sie dies nur, nachdem Sie CARTDATA() aufgerufen haben

6.12 GPIO

GPIO steht für „General Purpose Input Output“ und ermöglicht es Maschinen, miteinander zu kommunizieren. PICO-8 ordnet Bytes im Bereich 0x5f80..0x5fff GPIO-Pins zu, die


mit POKE() (um einen Wert auszugeben – z. B. um eine LED zum Leuchten zu bringen) oder mit @PEEK() (z. B. um

den Zustand eines Schalters abzurufen).

GPIO hat für verschiedene Host-Plattformen unterschiedliche Bedeutungen:

CHIP: 0x5f80..0x5f87 zugeordnet zu xio-p0..xio-p7
Pocket CHIP: 0x5f82..0x5f87 zugeordnet zu GPIO1..GPIO6
  // xio-p0 & p1 sind im Prototyping-Bereich im Gehäuse freigelegt.
Raspberry Pi: 0x5f80..0x5f9f zugeordnet zu wiringPi-Pins 0..31
  // siehe http://wiringpi.com/pins/ für Zuordnungen bei verschiedenen Modellen.
  // außerdem: Achte auf die unterschiedliche GPIO-Indizierung bei BCM und WiringPi!

Die Werte von CHIP und Raspberry Pi sind alle digital: 0 (LOW) und 255 (HIGH)

Ein Programm zum Ein- und Ausschalten beliebiger angeschlossener LEDs:

T = 0
FUNCTION _DRAW()
  CLS(5)
 FOR I=0,7 DO
    VAL = 0
    IF (T % 2 < 1) VAL = 255
    POKE(0X5F80 + I, VAL)
    CIRCFILL(20+I*12,64,4,VAL/11)
  END
  T += 0.1
END

■ Seriell

Für eine präzisere Zeitsteuerung kann der Befehl SERIAL() verwendet werden. GPIO-Schreibvorgänge werden gepuffert und am Ende jedes Frames versendet, was Taktzyklen mit höheren und/oder regelmäßigeren Geschwindigkeiten ermöglicht, als dies durch manuelles Bit-Banging mit POKE()-Aufrufen möglich ist.


SERIAL(CHANNEL, ADDRESS, LENGTH)

CHANNEL:
  0x000..0x0fe    entspricht den GPIO-Pin-Nummern; sende 0x00 für LOW oder 0xFF für HIGH
  0x0ff           Verzögerung; Länge wird als „Dauer“ in Mikrosekunden verstanden (ohne Overhead)
  0x400..0x401    ws281x-LED-Kette (experimentell)

ADDRESS: Der PICO-8-Speicherplatz, aus dem gelesen bzw. in den geschrieben werden soll.

LENGTH: Anzahl der zu sendenden Bytes. 1/8-Teile sind zulässig, um Teilbitstrings zu senden.

Beispiel: Um ein Byte bitweise an eine typische APA102-LED-Kette zu senden:

VAL = 42          -- ZU SENDENDER WERT
DAT = 16 CLK = 15 -- DATEN- UND TAKTPINS HÄNGEN VOM GERÄT AB
POKE(0X4300,0)    -- ZU SENDENDE DATEN (EINZELNE BYTES: 0 ODER 0XFF)
POKE(0X4301,0XFF)
FOR B=0,7 DO
  -- BIT SENDEN (HIGH ZUERST)
  SERIAL(DAT, BAND(VAL, SHL(1,7-B))>0 AND 0X4301 OR 0X4300, 1)
  -- TAKT ZYKLISCH TICKEN LASSEN
  SERIAL(CLK, 0X4301)
  SERIAL(0XFF, 5) -- 5 TAKTE VERZÖGERUNG
  SERIAL(CLK, 0X4300)
  SERIAL(0XFF, 5) -- 5 TAKTE VERZÖGERUNG
END

Zusätzliche Kanäle stehen für Byte-Ströme zum und vom Host-Betriebssystem zur Verfügung. Diese sind vor allem für UNIX-ähnliche Umgebungen bei der Entwicklung von Toolchains gedacht und stehen nicht zur Verfügung, wenn ein BBS oder ein exportiertes Modul läuft [1]. Die maximale Übertragungsrate beträgt in allen Fällen 64 kbit/s (blockiert die CPU).

0x800  verworfene Datei   //  stat(120) gibt TRUE zurück, wenn Daten verfügbar sind
0x802  verworfenes Image  //  stat(121) gibt TRUE zurück, wenn Daten verfügbar sind
0x804  stdin
0x805  stdout
0x806  Datei angegeben mit: pico8 -i Dateiname
0x807  Datei angegeben mit: pico8 -o Dateiname

In PICO-8 abgelegte Bilddateien erscheinen auf Kanal 0x802 als Byte-Stream in einem speziellen Format: Die ersten 4 Bytes geben die Breite und Höhe des Bildes an (jeweils 2 Bytes im Little-Endian-Format, wie bei PEEK2), gefolgt von dem Bild in Lesereihenfolge, ein Byte pro Pixel, farblich angepasst an die Anzeigepalette zum Zeitpunkt des Ablegens der Datei.

[1] Die Kanäle 0x800 und 0x802 sind in exportierten Binärdateien verfügbar, jedoch mit einer maximalen Dateigröße von 256 kB oder 128x128 für Bilder.

▨ Metatabellen

Metatabellen können verwendet werden, um das Verhalten von Objekten bei bestimmten Operationen zu definieren. Um beispielsweise Tabellen zur Darstellung von 2D-Vektoren zu verwenden, die addiert werden können, wird der Operator „+“ neu definiert, indem eine „__add“-Funktion für die Metatabelle definiert wird:

VEC2D={
  __ADD=FUNCTION(A,B)
     RETURN {X=(A.X+B.X), Y=(A.Y+B.Y)}
  END

▨ Coroutinen

Coroutinen bieten eine Möglichkeit, verschiedene Teile eines Programms in gewisser Weise parallel auszuführen, ähnlich wie bei Threads. Eine Funktion kann als Coroutine aufgerufen, mit


YIELD() beliebig oft angehalten und dann an denselben Stellen wieder fortgesetzt werden.

FUNCTION HEY()
  PRINT("DOING SOMETHING")
  YIELD()
  PRINT("DOING THE NEXT THING")
  YIELD()
  PRINT("FINISHED")
END

C = COCREATE(HEY)
FOR I=1,3 DO CORESUME(C) END


COCREATE(F)

Erstelle eine Coroutine für die Funktion f.


CORESUME(C, [P0, P1 ..])

Führt die Coroutine c aus oder setzt sie fort. Die Parameter p0, p1.. werden an die Funktion der Coroutine übergeben.

Gibt „true“ zurück, wenn die Coroutine ohne Fehler beendet wird.

Gibt „false“, Fehlermeldung zurück, wenn ein Fehler auftritt.

** Laufzeitfehler, die innerhalb von Coroutinen auftreten, führen nicht dazu, dass das Programm die Ausführung beendet. Es empfiehlt sich, CORESUME() in ein ASSERT() einzubinden. Wenn die Assertion fehlschlägt, wird die von coresume generierte Fehlermeldung ausgegeben.

YIELD

7.1 Anhang A: P8SCII-Steuerzeichen

Bei der Ausgabe mit PRINT() haben einige Zeichen eine besondere Bedeutung, mit der sich beispielsweise die Cursorposition und der Textdarstellungsstil ändern lassen. Steuerzeichen in PICO-8 sind CHR(0)..CHR(15) und können als Escape-Sequenz geschrieben werden („\n“ für Zeilenumbruch usw.)

Einige der unten aufgeführten Steuercodes nehmen Parameter entgegen, die nach einem Schema geschrieben werden, das eine Obermenge des Hexadezimalformats darstellt. Das heißt, '0'..'f' bedeuten auch 0..15. Aber auch Zeichen nach 'f' werden akzeptiert: 'g' bedeutet 16 und so weiter. Solche Parameter werden unten als P0, P1 geschrieben.

Beispiel: Um mit blauem Hintergrund („\#c“) und dunkelgrauem Vordergrund („\f5“) zu drucken:

PRINT("\#C\F5 BLUE ")

Die einzigen Auswirkungen auf den Zeichenzustand sind Änderungen der Cursorposition und der Vordergrundfarbe; alle anderen Attribute werden bei jedem Aufruf von PRINT() zurückgesetzt.

■ Steuercodes

0 "\0"   Beendet den Druckvorgang
1 "\*"   Wiederholt das nächste Zeichen P0-mal. ?"\*3a" --> aaa
2 "\#"   Zeichnet einen einfarbigen Hintergrund mit der Farbe P0
3 "\-"   Cursor horizontal um P0-16 Pixel verschieben
4 "\|"   Cursor vertikal um P0-16 Pixel verschieben
5 "\+"   Cursor um P0-16, P1-16 Pixel verschieben
6 "\^"   Sonderbefehl (siehe unten)
7 "\a"   Audio (siehe unten)
8 "\b"   Rücktaste
9 "\t"   Tabulator
a "\n"   Zeilenumbruch
b "\v"   Vorheriges Zeichen verzieren (siehe unten)
c "\f"   Vordergrundfarbe setzen
d "\r"   Wagenrücklauf
e "\014" Zu der unter 0x5600 definierten Schriftart wechseln
f "\015" Wechsle zur Standardschriftart

■ Sonderbefehle

Diese Befehle beginnen alle mit „\^“ und nehmen bis zu 2 Parameter (P0, P1) an. Beispiel: Um den Bildschirm auf Dunkelblau zu setzen: print("\^c1")

c cls auf Farbe P0, Cursor auf 0,0 setzen

g Cursorposition auf Startposition setzen

j zu absoluter Position P0*4, P1*4 (in Bildschirmpixeln) springen

■ Einzelne Zeichen

Zeichendaten können inline mit \^ angegeben und ausgegeben werden. Gefolgt von 8 Bytes roher Binärdaten oder \^: gefolgt von 8 zweistelligen Hexadezimalwerten. Das Datenformat entspricht dem von benutzerdefinierten Schriftarten; jedes Byte gibt eine Zeile von 1-Bit-Pixelwerten an, wobei das niedrigste Bit links steht .

\^.[8 Zeichen roher Binärdaten]
\^:[16 Zeichen Hexadezimal]

So druckst du eine Katze:

> ?"\^:447cb67c3e7f0106"

. und : rendern immer ein 8x8-Zeichen ohne Auffüllung. Um den Auffüllstatus zu berücksichtigen, verwende stattdessen , und ;.

> ?"\#3\^;447cb67c3e7f0106"

■ P8SCII-Outlines

Der Befehl „outline“ zeichnet zunächst jedes Pixel des Zeichens an bis zu 8 benachbarten Positionen, die durch ein 8-Bit-Bitfeld angegeben werden. Der Bitwert für jeden Nachbarn beginnt mit den niedrigsten Bits oben links und steigt in Leserichtung an:

0x01    0x02    0x04
0x08     --     0x10
0x20    0x40    0x80

Das erste Zeichen nach dem Befehl „\^o“ ist die Farbe, und die folgenden beiden Zeichen sind das Nachbar-Bitfeld in Hexadezimal. Um beispielsweise links von jedem Vordergrundpixel ein Pixel zu zeichnen, kann der Wert 0x01 verwendet werden:

> ?"\^o801hey"

Das Folgende zeichnet ein blaues Pixel links, rechts, oben und unten von jedem Vordergrundpixel, was den Bits 8+16+2+64 = 90 entspricht, oder 0x08+0x10+0x02+0x40 = 0x5a in Hexadezimal:

> ?"\f7\^oc5aoutline"

Schließlich lässt sich ein vollständiger Umriss erzielen, indem alle Bits gesetzt werden. „Outline“ funktioniert in Kombination mit den Befehlen „tall“ und/oder „wide“, aber der Umriss wird weiterhin mit einer Dicke von einem Pixel gezeichnet:

> ?"\fe\^w\^t\^o7ffchunky"

Das Zeichnen einer Kontur kostet etwa doppelt so viel CPU-Leistung wie das Zeichnen eines Zeichens ohne Kontur.

Der Parameter für die Konturfarbe kann „$“ sein, um die aktuelle Farbe zu verwenden, oder „!“, um die aktuelle Farbe zu verwenden und das Zeichnen des Innenbereichs zu überspringen.

> ?" \^o!ff empty interior"

■ Dekorationszeichen

Das Steuerzeichen \v kann verwendet werden, um das zuletzt gedruckte Zeichen mit einem anderen Zeichen an einem bestimmten Offset zu verzieren, ohne dass die Cursorposition anderweitig verwaltet werden muss. Nachdem das Verzierungszeichen gedruckt wurde, wird die vorherige Cursorposition wiederhergestellt.

Das Format lautet \v P0 char, wobei P0 eine Zahl ist, die den gewünschten Offset angibt, und char ein beliebiges Zeichen ist, das an diesem Offset (relativ zum vorher gedruckten Zeichen) gedruckt werden soll.

Der Offset hat x in den untersten 2 Bits gepackt und beginnt (-2,-8) in der Lesereihenfolge. Somit bedeutet 3 (+1, -8), 4 bedeutet (-2, -7) und so weiter.

Um beispielsweise „cafÃ©!“ zu schreiben und dabei ein Komma zur Darstellung des Akzents zu verwenden:

PRINT"\NCAFE\VB,!"

In diesem Fall ist P0 'b', was als die Zahl 11 gelesen wird. Das Komma wird also an folgender Stelle eingefügt:

x = (11 % 4) - 2 = 1
y = (11 \ 4) - 8 = -6

■ Benutzerdefinierte Schriftart

Eine benutzerdefinierte Schriftart kann unter 0x5600 definiert werden und besteht aus 8 Bytes pro Zeichen * 256 Zeichen = 2048 Bytes. Jedes Zeichen ist ein 8x8-Bitfeld (1 Bit/Pixel), wobei, von oben beginnend, jede Zeile ein einzelnes Byte ist, das links mit 0x1 beginnt.

Die ersten 128 Bytes (die Zeichen 0 bis 15 werden nie gezeichnet) beschreiben die Attribute der Schriftart:

0x5600 Zeichenbreite in Pixeln (kann mehr als 8 betragen, es werden jedoch nur 8 Pixel gezeichnet)
0x5601 Zeichenbreite für Zeichen 128 und höher
0x5602 Zeichenhöhe in Pixeln
0x5603 Zeichenversatz x
0x5604 Zeichenversatz y
0x5605 Flags: 0x1 apply_size_adjustments 0x2: Tabulatoren relativ zur Cursor-Ausgangsposition anwenden
0x5606 Tabulatorbreite in Pixeln (wird nur verwendet, wenn eine alternative Schriftart gezeichnet wird)
0x5607 ungenutzt

Die verbleibenden 120 Bytes dienen zur Anpassung der Breite und des vertikalen Versatzes der Zeichen 16..255. Jedes Nibble (niedrige Nibbles zuerst) beschreibt die Anpassungen für ein Zeichen:

Bits 0x7: Zeichenbreite um 0, 1, 2, 3, -4, -3, -2, -1 anpassen
Bit 0x8: Wenn gesetzt, Zeichen einen Pixel höher zeichnen (nützlich für lateinische Akzente)
